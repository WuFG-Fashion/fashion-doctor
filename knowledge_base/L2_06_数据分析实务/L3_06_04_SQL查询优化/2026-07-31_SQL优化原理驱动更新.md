# L3_06_04 SQL查询优化 — 2026-07-31 更新纪要

> 本轮（ingestC Round 117）补充 SQL 性能优化 2026 原理驱动跃迁，与 L2_06 数据分析实务直接相关。

## 新增要点

- **范式转变**：2026 年 SQL 优化从"规则背诵"转向"原理驱动"——以 `EXPLAIN ANALYZE` 真实执行数据为准。
- 真实案例：用户行为分析查询 47 秒（type=ALL, rows=8500万）→ 加复合索引 0.3 秒，**157 倍提速**；用户画像查询 12 秒 → 0.3 秒。
- 覆盖索引真相：SELECT * 的真正杀手是破坏覆盖索引导致回表，合理覆盖索引有 **10x+** 差异。
- 子查询改 JOIN：旧版 MySQL 每执行一次子查询即全表扫描，改 JOIN 差 **10 倍**。
- 云原生架构：存算分离（DuckDB/ClickHouse + S3）、物化视图动态刷新、PG17+ 自适应执行计划、JSONB 融合。
