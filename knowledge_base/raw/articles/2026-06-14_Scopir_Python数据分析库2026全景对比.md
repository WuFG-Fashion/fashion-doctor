### Polars PDS-H (TPC-H衍生，2025年5月)
- **Polars在全部22个TPC-H衍生查询中均大幅领先Pandas**
- 内存占用远低于Pandas

- 大规模DataFrame合成数据分析：Polars能耗约为Pandas的**1/8**
- 大数据集TPC-H风格查询：Polars仅消耗Pandas约**63%**的能量

### 性能梯队
| 梯队 | 库 | 性能特征 |
|------|-----|---------|
| 第一梯队 | Polars & DuckDB | 百万行以上数据集显著快于Pandas |
| 聚合强项 | DuckDB | groupby和大量join的工作负载表现突出 |
| 提速有限 | Modin | 相对Pandas有一定提速，但更高内存消耗 |
| 明显改善 | Pandas 2.x + Arrow后端dtype | 比1.x版本明显更快 |

## 各库深度分析

### Polars — 性能优先场景新标杆

**优点：**
- 大多数操作显著快于Pandas（官方基准验证）
- 惰性求值优化查询计划
- 一致的API设计，避免Pandas各种陷阱（SettingWithCopyWarning等）
- Rust实现，原生并行，默认利用所有核心

**缺点：**
- 生态差距：很多库只接受Pandas DataFrame
- 可视化集成较弱（Matplotlib/Seaborn预期Pandas输入）
- API差异大，有Pandas经验的团队约需**一周**适应期

### DuckDB — SQL用户的终极选择

**优点：**
- 出色的聚合性能，groupby和join操作与Polars不相上下甚至更快
- **零拷贝集成**——SQL查询可直接引用Pandas、Polars和Arrow数据
- 直接读取Parquet、CSV、JSON，无需显式加载
- 嵌入式，无服务器、无配置，`pip install duckdb` 即可

### Pandas 2.2 — 依然能打（有条件）

**继续用Pandas的场景：**
- 团队已非常熟悉，且性能满足需求
- 需要最大程度的库兼容性（scikit-learn、statsmodels等）
- 小数据集（不到100万行），性能差异可忽略
- Jupyter Notebook中做探索性分析

**应切换的场景：**
- 数据集超出可用内存
- 构建对性能有要求的生产数据管道
- 经常处理超过千万行的数据集

### Modin — 不推荐

- 内存占用更高，需跨进程分发数据
- API覆盖不完整，部分操作会静默回退到Pandas
- 启动开销大，小数据集上反而更慢
- 分布式执行出问题时难以排查

> **结论：要兼容性就继续用Pandas，要性能就切换到Polars。Modin处于两头不靠的尴尬位置。**

## 快速决策树

```
数据不到100万行？
  → Pandas（用Arrow后端dtype）完全够用

团队更习惯SQL？
  → DuckDB

构建Python数据管道？
  → Polars

想直接查询文件而不加载？
  → DuckDB

单机数据超过1亿行？
  → Polars（lazy模式）或DuckDB

数据大于可用内存？
  → DuckDB或Polars（流式模式）
```
