# AI Agent 正在改变商品计划：从事后复盘到提前决策

> 一句话摘要：AI Agent 不替商品团队做决定，而是把商品计划从"一次性作业"推向"持续推演"，实现 7×24 小时监控、动态推演与提前决策，让决策窗口从"事后"拉到"事前"。

> 来源：第七在线，发布于 InfoQ 写作社区，2026-07-10，URL https://xie.infoq.cn/article/337699ac36cdbac74de07122a
> 最后更新：2026-08-03

## 核心观点

传统商品计划节奏固定（季前做 OTB、定品类结构、拆首单/追单比例、拉周转目标），假设计划期内市场稳定。但华南降温、抖音爆款、竞品价格战、上游交期延迟等任一变量都会让首单比例、品类结构、可销周数偏离预设。过去需 2–3 天的跨部门分析，AI Agent 辅助下可压缩至数小时——系统在夜间自动更新数据并多情景模拟，次日一早上推演结果与建议。

## AI Agent 改变商品计划的五个关键变化

1. **从"一次性作业"到"持续推演"**：计划从"定稿"变"活页"，按数据刷新节奏（T+1 日报、实时销售、库存变动、外部变量）在业务规则与触发条件下自动推演，评估库存周转、可销周数、毛利率底线变化。
   - 案例：卫衣在华东区销售增速连续三天超预期 30%，可销周数从 4 周压缩至 1.6 周。Agent 建议将华南同 SKU 调拨过来，调剂后华东可销周数恢复至 3.2 周，预计**多实现销售 28 万、调拨成本约 1.2 万、品类整体售罄率提升约 2.3 个百分点**。
2. **从"人盯报表"到"Agent 主动预警+根因诊断"**：解决延时、靠运气、看表象不看根因三缺陷。
   - 案例：华北 11 家门店某 SKU 可销周数降至 1.2 周，**低于公司 2 周安全线**。根因是首单比例偏低（首单 30%，原计划 35%）+ 上周气温骤降拉高需求。建议本周追加补货，优先覆盖可销周数最低 5 家门店，**预估需追加 250 件**。
3. **从"经验说了算"到"经验可验证、可校准"**：AI 不否定直觉，而是用数据校准。
   - 案例：判断首单比例从 40% 提到 45%——方向正确概率 72%。但提示该价格带在华东市场近两年转化率下滑 15%，若延续，首单提到 45% 会导致该区域库存周转天数拉长 12 天。
4. **从"开会对齐"到"统一经营模型"**：维护统一经营模型（销售目标、OTB 预算、品类结构、首单比例、库存周转、可销周数底线、现金流、毛利率底线同模型实时联动）。会议从"对齐口径"转为"讨论取舍"。
5. **从"事后复盘"到"事前沙盘推演"**：决策落地前多情景模拟（暖冬风险、OTB 下调影响、竞品价格战最坏现金流）。"以前像大雾里开车，现在至少有了导航。"

## AI Agent 生效的四个前提（差一个即落不了地）

1. **数据打通**：POS/ERP/财务系统 T+1 打通、口径一致（"售罄率""可销周数""品类结构"全系统同一算法）。
2. **规则建模**：首单比例上下限、可销周数安全线、库存周转警戒/红线、补货触发条件等必须业务定义清楚。
3. **权限机制**：Agent 可预警/推演/生成建议，但**不能替人拍板**；需分级（触线通知 / 建议待确认 / 管理层决策）。
4. **业务闭环**：从预警→人工判断→决策执行→结果反馈回流 Agent，否则 Agent 只是"很贵的消息推送系统"。

## 关联页面

- 商品企划主概念：动态 OTB 管理、柔性供应链与商品企划
- 指标口径：售罄率、可销周数、库存周转天数、库销比的统一定义（数据打通前提）
- 数据治理：渠道数据孤岛是 Agent 推演无效的根因
