## Markdown 内容

本文基于论文《Forecasting New Product Life Cycle Curves: Practical Approach and Empirical Analysis》整理。原文发表于 Manufacturing & Service Operations Management，作者包括 Kejia Hu、Jason Acimovic、Francisco Erize、Douglas J. Thomas 和 Jan A. Van Mieghem。本文以“阅读笔记”的方式进行解读，尽量保持原文深度，同时补充必要术语说明，帮助读者理解模型与图表背后的业务含义。一句话概括：这篇论文不是简单地问“新产品每周能卖多少”，而是把问题改写为“这个新产品的需求曲线，会像过去哪一类产品”。

# 一、问题起点：新产品不是完全没有历史
很多企业在做新产品预测时，仍然依赖市场调研、销售判断、管理层经验或产品团队输入。这些方法有价值，尤其适用于完全创新的产品；但原文提醒我们，很多所谓“新产品”并不是从零开始。
- 它可能是新一代型号。
- 也可能是新配置、新包装或新渠道版本。
- 它没有自己的销售历史，但往往有相似的前代产品或同类产品。因此，这篇论文的核心思路是：如果新产品与历史产品相似，就可以利用历史产品的产品生命周期曲线（PLC，Product Life Cycle）来预测它未来的需求走势。阅读提示：这篇论文的价值，不在于提出一个更复杂的算法，而在于把新产品预测从“单点销量预测”转向“生命周期形状识别”。
# 二、经典PLC曲线与真实短生命周期产品

![图片](https://mmbiz.qpic.cn/sz_mmbiz_png/eWdetJX1j3jUF08Ck72e9LQPIFcfcBSgicK3pAicLGQeOOdvgN3L2FBB3icOCgYSVqcniawribYW88lblwu0nJq01g5QbMXYnKGx39VlK3tzOHlA/640?wx_fmt=png)

图1：典型PLC曲线与实际SKU需求曲线对比图1左侧是教材式的典型产品生命周期：引入期、成长期、成熟期、衰退期。右侧则是 Dell 数据中某个 SKU 的实际订单曲线。两者对比后，一个很明显的现象是：现实中的短生命周期科技产品，往往没有很长、很稳定的成熟期。
- Introduction，引入期：产品刚上市，需求开始出现。
- Growth，成长期：市场接受度提升，需求快速增长。
- Maturity，成熟期：需求进入相对稳定平台。
- Decline，衰退期：新产品替代或市场热度下降，需求走弱。原文后续进一步验证：约20%的产品生命周期没有成熟期；50%的产品成熟期少于整个生命周期的13%；75%的产品成熟期少于整个生命周期的35%。这说明，对短生命周期产品来说，“稳定需求”并不是常态。管理含义：如果产品大部分时间都处于爬坡或下滑阶段，那么用稳定均值来做库存和产能计划，就很容易错配。

# 三、三步预测框架——拟合、聚类、预测

![图片](https://mmbiz.qpic.cn/sz_mmbiz_png/eWdetJX1j3jV6ZP6Ua43ZYUF3NFYjJSTbgtnphVKruZJndwu4icDb6bxklhiaqhDIvoTaBswPyB7ME2sImwXVYDicDT2Zhf39hliaMkSs6WXfIE/640?wx_fmt=png)

图2：预测流程包含拟合、聚类和预测三步

原文提出的方法可以概括为三步：Fitting、Clustering、Forecasting。
- Fitting：先用历史订单数据拟合每个历史产品的生命周期曲线。
- Clustering：再把生命周期曲线形状相似的产品分为一组。
- Forecasting：最后用相似产品组的代表曲线，生成新产品的预测。简单说，这不是先问“新产品周销量是多少”，而是先问“它的需求形状像哪一类历史产品”。关键转变：先预测形状，再根据生命周期长度和总销量，把形状缩放成具体周需求。

# 四、先看懂几个关键术语
Bass diffusion curve（Bass扩散曲线）：一种经典的新产品扩散模型，用“创新者”和“模仿者”的采纳过程解释需求增长。它更像理论模型，强调需求为什么扩散。Polynomial curve（多项式曲线）：用二次、三次、四次等多项式拟合历史需求曲线。优点是拟合能力强，缺点是业务解释性较弱，参数含义不直观。Piecewise-linear curve（分段线性曲线）：把生命周期拆成几段直线，例如上升、平台、下降。它不追求光滑，而追求简单、直观、可解释。Triangle（三角形曲线）：一种没有明显成熟期的平台结构，需求从上升到峰值后直接下降，适合快速起落的短生命周期产品。Trapezoid（梯形曲线）：在三角形基础上增加一个短平台期，能够表达 ramp-up、plateau、ramp-down 三个阶段。Smooth curve（平滑曲线）：如多项式、Bass曲线等连续光滑模型，曲线更柔和，但不一定最适合解释业务阶段。Ramp-up / Plateau / Ramp-down：分别指需求爬坡、平台期、需求回落，是planner更容易理解的业务语言。
# 五、数据基础：为什么必须先标准化？

![图片](https://mmbiz.qpic.cn/sz_mmbiz_png/eWdetJX1j3j8ILiaVfrx8qIVjoldyR6HrozyshrRjbSfsQEkHba1LcFsicBBNZUX7XCYP5DNJEvN3sbA4PD31fia4Xp23iaO6DWuOfZPAau63VY/640?wx_fmt=png)

表1：数据预处理后的统计摘要论文使用 Dell 北美市场 170 个 MTS 产品的订单数据，覆盖超过400万台电脑。表1显示，不同品类产品的销量规模和生命周期长度差异明显。这就带来一个问题：如果直接比较原始销量，我们比较到的可能只是“谁卖得多”，而不是“谁的需求走势相似”。因此，论文先做标准化：
- 销量标准化：将每个产品生命周期总销量标准化为1。
- 时间标准化：将不同长度的生命周期拉到可比较的统一尺度。标准化之后，比较对象从“销量大小”变成“曲线形状”。这是全文方法成立的关键。

# 六、预测误差改善来自哪里？

![图片](https://mmbiz.qpic.cn/mmbiz_png/eWdetJX1j3gHpD1ELOYCiacnpiamsPyKm9rElc6CfDacF3t1dd787XVyPBQaPP6YrWYyeic3aVf9J6qqxullXPWiaCepLv7y9nvVlAs8qa6dkV0/640?wx_fmt=png)

图3：不同曲线模型相对 Dell 内部预测的误差改善图3比较了不同曲线方法相对 Dell 内部预测的改善。这里出现两个重要指标：MASE 和 SAE。MASE（Mean Absolute Scaled Error，平均绝对缩放误差）：一种经过缩放处理的预测误差指标，便于跨SKU比较。MASE越低，说明预测越好。SAE（Sum of Absolute Errors，绝对误差总和）：直接把一组SKU的绝对误差加总，更能反映组合层面的总误差，通常大销量SKU影响更大。结果显示，trapezoid 方法在 MASE 与 SAE 上均可带来约2%–3%的误差改善。这个改善幅度看似不大，但在年销量百万级的硬件业务中，可能意味着可观的库存和运输成本节省。

![图片](https://mmbiz.qpic.cn/mmbiz_png/eWdetJX1j3jgpL0XKZnBOlNg7LUhWWvmrjSibmgvUq9PJN0wv9ibQG0JCcPkA2WfuhLkwia10F4GGYkpSzCwoXUuYOYwHOPG06vj5VqN3DmmAs/640?wx_fmt=png)

- feature-based clustering 需要产品特征信息，比如CPU、RAM、硬盘等。
- category-based clustering 需要产品类别信息，比如 laptop、desktop。
- data-driven clustering 主要依赖历史需求曲线，因此适用范围更广。

# 九、成熟期可能比我们想象得短

# 十、真正的相似，可能来自需求形状

![图片](https://mmbiz.qpic.cn/mmbiz_png/eWdetJX1j3hLDTEtShomRqNNm8EgCwbSvcgR0ibP2UebmaRic1JCEcbvduVAM0Utic6jXS0kPmyyN9v68ibfSHNdXpKRRZW1sh68G2UzC4ia2nM0/640?wx_fmt=png)

图7：基于 poly4 与 trapezoid 的时间序列聚类时间序列聚类（time-series clustering）是本文非常关键的一步。它不是按产品配置或类别来分组，而是根据生命周期曲线形状来分组。feature-based clustering（特征聚类）：按产品配置或属性分组，例如CPU、RAM、硬盘大小。category-based clustering（类别聚类）：按产品大类分组，例如 laptop、desktop、workstation。data-driven clustering（数据驱动聚类）：不预先依赖业务标签，而是根据数据本身形成分组。time-series clustering（时间序列聚类）：数据驱动聚类的一种，专门比较不同时间序列的形状相似性。图7显示，不同SKU的生命周期曲线可以被分为几种典型形状。有些早期达到峰值，有些后期才放量，有些则生命周期内持续增长。管理含义：产品相似性不一定来自“产品长得像”，也可能来自“需求走得像”。

# 十二、如何把一组历史产品变成一条预测曲线？

![图片](https://mmbiz.qpic.cn/mmbiz_png/eWdetJX1j3jsUlfpwnedw5xX72N32fWfsJINepv8uKwRw1bIxNxW7JAibHkiaOayCLuPoHOvQTGE6zqjA3QsxmZGqXUCUkL2EKdKiaEAaNibJFE/640?wx_fmt=png)

图8：GenerateAvg 与 GenerateFit 两种代表曲线生成方式完成聚类后，还需要把一个cluster中的多条历史曲线凝练成一条可用于新产品预测的代表曲线。论文比较了两种方式。GenerateAvg：对cluster内的曲线逐点取平均，得到“平均形状”。这种方式直观，但可能保留较多噪声。GenerateFit：将cluster内所有曲线重新拟合为一条代表性曲线，例如重新拟合一条 trapezoid 或 poly4 曲线。这种方式更强调提炼共同结构。论文结果显示，trapezoid + GenerateFit 的组合表现非常好。预测的关键，不只是找到相似产品，还要把相似性压缩成一条可以用于计划决策的曲线。

# 十六、预测数量之外，更重要的是拐点

![图片](https://mmbiz.qpic.cn/sz_mmbiz_png/eWdetJX1j3iaBozq7PFMexMCXh3BPwANoDwsACWCpM8Rk71Ju7Yju0OTtibLAQAzzvtiawBAF8otMHjxC29gEwlfz98eK3d167lUmkiaj4CSl0w/640?wx_fmt=png)

- 什么时候开始放量，决定是否提前备货。
- 什么时候达到峰值，决定是否继续加产能。
- 什么时候开始下滑，决定是否减少供应承诺和准备EOL。在新产品管理中，比“预测有多少需求”更重要的，是“判断需求什么时候发生变化”。

# 十九、从论文到实践：方法步骤与 S&OP 落地框架
读完前面的模型与结果后，可以把这篇论文进一步转化为一个更容易落地的流程。它不是要求企业完全替换现有预测流程，而是在 S&OP / Demand Review 中增加一层“生命周期曲线”的判断。1. 三步方法：从历史数据到新产品预测如果用业务语言重写论文方法，可以概括为三步。Step 1：识别需求形状（Fit）
- 输入：历史SKU的订单数据，最好是经过清洗后的净需求数据。
- 动作：拟合历史产品的生命周期曲线，可以优先考虑 trapezoid 或 triangle 这类分段线性曲线。
- 输出：每个历史SKU对应一条标准化后的生命周期曲线。
- 管理含义：这一步不是为了证明某个模型最复杂，而是为了看清产品需求从 ramp-up 到 plateau 再到 ramp-down 的基本结构。Step 2：找到相似产品（Cluster）
- 输入：历史产品的标准化生命周期曲线。
- 动作：按照需求曲线形状进行聚类，优先使用 time-series clustering，而不是只依赖产品类别或配置。
- 输出：若干类“需求轨迹相似”的产品群。
- 管理含义：相似产品不一定是产品属性最像，而是需求路径最像。Step 3：生成新产品预测（Forecast）
- 输入：新产品的预计生命周期长度、预计总销量、所属相似产品群。
- 动作：用相似产品群的代表曲线生成新产品的生命周期形状，再做时间缩放和数量缩放。
- 输出：新产品从上市到退市的完整周度或月度需求曲线。
- 管理含义：预测不再只是未来几期的数字，而是一条可用于供应链决策的时间路径。简化公式：新产品预测 = 历史相似需求形状 × 生命周期长度 × 总销量规模。

2. 与 S&OP 流程的连接这套方法最适合嵌入 S&OP，而不是孤立地作为一个统计模型存在。它可以放在 Demand Review 到 Supply Review 之间，帮助团队把“一个总量预测”转化为“随时间变化的需求路径”。

| S&OP环节 | 传统关注点 | 本文方法可补充的内容 | 可操作输出 |
| --- | --- | --- | --- |
| Product / Portfolio Review | 新品上市计划、生命周期长度、替代关系 | 识别新产品是否有类似历史产品；确认可能的前代SKU或相似SKU池 | 相似SKU清单、生命周期假设 |
| Demand Review | 销售预测、市场判断、客户输入 | 用历史相似产品生成PLC曲线，形成按周/月展开的需求路径 | 完整生命周期需求曲线、峰值时间、拐点时间 |
| Supply Review | 产能、物料、库存、供应风险 | 基于 ramp-up / plateau / ramp-down 判断供给节奏，而不是只看平均需求 | 产能爬坡计划、采购节奏、库存策略 |
| Pre-S&OP | 需求与供应差异、方案权衡 | 比较不同PLC场景：乐观/基准/保守，讨论缺货、过量库存和EOL风险 | 场景对比、风险敞口、决策选项 |
| Executive S&OP | 关键决策审批 | 围绕拐点、峰值和生命周期末端做管理决策 | 产能承诺、库存上限、EOL策略、管理层决策 |

3. 三个典型落地场景场景一：新产品上市前
- 用产品/市场团队提供的生命周期长度，结合销售或市场团队提供的总销量判断。
- 模型负责提供需求形状，planner 再结合促销、客户项目、替代关系进行调整。
- 输出可以直接用于产能预留、关键物料采购和运输方式选择。场景二：生产与库存规划
- ramp-up阶段：关注产能和物料能否提前爬坡。
- plateau阶段：关注服务水平与库存成本平衡。
- ramp-down阶段：关注控产、控货和避免呆滞库存。场景三：End-of-Life 管理
- 利用拐点预测识别需求下降窗口。
- 提前调整采购承诺和生产节奏。
- 配合库存清理、替代产品切换和EOL策略，降低 obsolete 风险。S&OP中的价值：这个方法本质上是把“预测”从一个数字，变成一个可讨论、可调整、可决策的时间结构。

# 二十、结语：从预测工具，到供应链决策结构
如果把这篇论文放在更大的供应链视角来看，它真正解决的并不只是预测问题，而是一个更底层的管理问题：企业如何在新产品尚无自身历史数据时，仍然提前做出较好的供应链决策。传统预测往往是逐周给数字，然后随着真实需求出现不断修正。这种方式在长提前期、短生命周期产品上会遇到困难：等需求已经被看清，很多采购、产能和运输决策已经发生。本文方法的价值在于，它尝试在上市前就给出完整生命周期的需求路径，让供应链可以更早进入准备状态。这背后有四个重要转变。第一，从“预测数值”转向“预测形状”。单周销量是结果，生命周期曲线才是结构。只有看清结构，才知道需求什么时候爬坡、什么时候见顶、什么时候回落。第二，从“产品相似”转向“需求相似”。产品规格相似并不必然代表需求轨迹相似。对预测来说，真正有价值的是找到需求变化方式相似的历史产品。第三，从“后期修正”转向“前期判断”。越往后修正，供应链成本越高。尤其在长供应链提前期下，前期判断的质量直接影响库存、产能和运输决策。第四，从“提高预测精度”转向“减少错误决策”。预测不是为了在指标上赢，而是为了减少缺货、过量库存、加急运输和生命周期末端呆滞。因此，这篇论文最值得带走的不是某一个具体模型，而是一种思考方式：新产品预测可以不是从零猜未来，而是从历史产品中找到相似的生命周期结构，并将这种结构迁移到新产品上。新产品预测，不是从零开始，而是基于历史相似轨迹的“结构复用”。对供应链来说，这句话还可以再换成一种更实际的表达：与其不断调整预测，不如一开始就构建一条更接近真实的需求路径，并把它放进 S&OP 中，转化为产能、物料、库存、运输和EOL管理的具体决策。
