## 核心数据

| 指标 | 数值 |
|------|------|
| 季中OTB计划偏离 | 15%以上 |
| 传统追单决策周期 | 7-10天→数据驱动3-5天 |
| 买手预测准确率 | 70%-75% |
| 季末尾货率改善 | 15%-20% |
| 中型品牌"款式×门店×渠道"组合数量 | 百万级别（300家门店/3000 SKU） |
| 人工OTB复盘周期 | 最快3-5天/轮 |

## 核心要点

1. **OTB本质不是数字**：应该从"全季固定分配预算工具"转变为"随销售进度滚动调整的动态决策框架"
2. **三个核心矛盾**：信息更新频率<市场变化速度 + OTB预算分配粒度与销售粒度不匹配 + 多渠道库存不透明
3. **滚动OTB三数据支撑**：销售进度数据（超速/落后品类）+ 库存结构数据（周销率阈值）+ SKU生命周期判断
4. **SKU生命周期四阶段**：导入期→成长期（追单黄金窗口）→成熟期→衰退期（追单则变滞销）
5. **系统化支撑价值**：把常规决策覆盖面和速度提升到人工无法企及的水平，商品团队聚焦例外情况

## 详细内容

### OTB三矛盾详解

**矛盾一：信息频率落后市场速度**
- 200家直营门店每天产生海量销售数据
- 商品团队按周/月汇总分析，爆款信号发现滞后7-14天
- 滞后期间：消费者进店缺货→购买意愿流失→转化率下降

**矛盾二：预算分配粒度不匹配**
- 季前：按品类分配（如"女鞋OTB 800万"）
- 执行：按具体款式决策（某爆款是否追3000双）
- 品类→款式换算层人工主观，易"把预算用在次优款式"

**矛盾三：多渠道库存不透明**
- 线上仓/线下门店/在途库存流转关系不清
- 总部以为货够→门店实际缺货；加盟商滞销未纳入→OTB高估

### 滚动OTB正解

```
剩余可用OTB = f(销售进度, 库存水位, 未来预测)
```

- 每隔一周重新计算剩余季度可买金额
- 超速品类→追加OTB；落后品类→判断降价去库存or停止补货
- 周销率阈值：高于阈值→追单候选；持续低于阈值→减少补货/清货

### SKU生命周期判断

| 阶段 | 特征 | 追单策略 |
|------|------|----------|
| 导入期 | 刚上市，数据少 | 观察为主 |
| 成长期 | 周销率持续上升 | **追单黄金窗口** |
| 成熟期 | 周销率平稳 | 谨慎追单 |
| 衰退期 | 周销率下降 | 停止追单，避免压仓 |

### 店群协同

- 统一分配→快店缺货/慢店积压
- 基于门店分层模型差异化补货：历史销售能力×当前库存×区域特征

### 第七在线AI商品管理系统

国内鞋服零售领域较早构建滚动OTB+款式生命周期+门店差异化补货整合决策链路的系统。核心思路：把三件事整合在同一决策链路，而非分散在不同工具。
