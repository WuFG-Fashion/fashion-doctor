## 一、开篇案例：50 万件碎花裙

某服装品牌商品总监押注一款碎花连衣裙，备货 **50 万件**。结果天气热得早、碎花没火、简约风突然爆了——库存成压仓石，**打到三折才清掉，一个季度亏 2000 万**。

## 二、服装行业四个"致命"特征

| 特征 | 具体表现 | 对指标体系的要求 |
|------|---------|----------------|
| 生命周期极短、SKU 极多 | 一件衣服通常只有 3–6 个月：导入期 1–2 周 / 成长期 2–4 周 / 成熟期 4–8 周 / 衰退期 2–4 周；一年开发上千 SKU | 要能跟踪**每个 SKU 的生命周期**，而不是只看总销售额 |
| 流行趋势变化快 | 受天气、明星、社媒种草、竞品爆款多重影响 | 要能**捕捉趋势变化**，而不是等趋势过去才知道 |
| 款/色/码维度爆炸 | 一款 T 恤 5 码 × 4 色 = 20 个 SKU，各自独立管库存 | 要能下钻到"**尺码 × 颜色**"级别 |
| 库存风险高、占资金 | 过季衣服价值可能只剩 **30%**；断码难卖；颜色不流行打折也难清 | 要能**预警库存风险**，而不是积压后才知道 |

## 三、五维一体核心框架

### 第一维 商品——款对不对？
爆款指标（销量/销售额 TOP10、爆款贡献占比、爆款生命周期）、新品指标（新品动销率、上市 30/60/90 天存活率、新品贡献率）、品类结构（上衣/裤子/裙子/外套占比、增长率、毛利率）、价格带（分布、毛利率、折扣率）、款式属性（版型/领型/袖长/裙长）。
> 最核心：**爆款识别**（要在萌芽期就识别并快速追单）与**新品存活率**（上市 30 天还在卖的 SKU 比例，低说明选款有问题）。

### 第二维 销售——卖得好不好？
规模（销售额/销量/订单量/客单价）、增长（同比环比、同店增长）、效率（售罄率、连带率、件单价）、折扣（平均折扣率、折扣销售占比、正价销售占比）。
> 最核心：**售罄率 = 已售数量 / 总到货数量**——**上市 30 天售罄率低于 30% 可能有问题；60 天低于 50% 是危险信号**；**连带率 = 总件数 / 订单数**，越高说明搭配做得好。

### 第三维 库存——压不压货？
周转（周转天数、周转率）、结构（新旧品/品类/尺码库存占比）、健康度（库龄 30/60/90/120 天+ 分布、呆滞库存占比、断码率）、风险（红黄绿灯预警、季末库存预测、清仓进度）。
> 最核心：**库龄**（超过 90 天基本就是死库存）与**断码率**（尺码齐全度，断码严重的 SKU 即使总量不少也很难卖）。

### 第四维 渠道——在哪卖？
渠道表现（销售额占比/增长率/毛利率）、渠道效率（ROI/费用率/退货率）、线上线下（线上占比、线下同店、O2O 渗透率）。渠道极其多元：直营店/加盟店/百货专柜/奥莱；天猫/京东/抖音/快手/小程序/唯品会；直播带货/私域社群/小红书种草。

### 第五维 用户——谁在买？
流量（访客数、新老客占比）、转化（转化率、复购率、流失率）、价值（客单价、ARPU、LTV）、画像（年龄/性别/城市/消费力/风格偏好）。
> 最核心：**复购率**与**风格偏好**（甜美/简约/通勤/运动，是选款与推荐的核心依据）。

## 四、落地四步法

**第一步 定目标找对齐**——按阶段选北极星指标：

| 阶段 | 关注 | 北极星指标 |
|------|------|-----------|
| 品牌初创期 | 打品牌、做爆款 | 爆款贡献率 |
| 快速扩张期 | 开店、铺渠道 | 销售额或门店数 |
| 精细化运营期 | 控库存、提效率 | 售罄率或库存周转天数 |
| 用户运营期 | 做复购、提 LTV | 复购率或 LTV |

**第二步 盘数据清家底**——数据源分散在 POS / 电商平台后台 / ERP / CRM / 商品主数据系统 / WMS。打通的四个关键：
1. **SPU/SKU 编码统一**（同一商品在 POS、ERP、电商平台编码一致）
2. **尺码/颜色标准化**（XS/S/M/L/XL 统一映射，"黑色"不能有的系统叫"黑"）
3. **时间口径对齐**（自然周月与财周财月要对齐）
4. **渠道 ID 统一**

**第三步 定指标建字典**——服装指标定义的四个特殊难点：售罄率的分母是总到货量还是总采购量、时间范围 30/60/90 天？库存周转天数分母是销售成本还是销售收入、不同品类标准是否不同？断码怎么算（缺 1 个尺码算不算，缺 2 个呢）？新品指上市多少天内（7/15/30 天）？
> 原则：**一个指标，一个口径**；不同品类、渠道、季节要能横向对比。

**第四步 分场景做应用**：CEO/品牌总监看战略驾驶舱（北极星趋势、品类与渠道结构、异常预警）；商品企划/买手看商品看板（TOP50 爆款识别、新品动销与存活、价格带、款色码分析）；运营看销售看板（销售达成、同店、折扣率、连带率、分渠道分区域）；供应链看库存看板（周转、库龄分布、售罄追踪、补货建议、呆滞预警、清仓进度）。

## 五、实战案例：某女装品牌 200 店 / 年销 8 亿

定位 25–35 岁都市女性，**200 家直营店**，天猫 + 抖音双渠道，年销售额 **8 亿**。

- **盘数据发现的问题**：线上线下数据割裂（同一会员两套 ID）、尺码颜色命名不统一（"S 码"有的系统叫"小号"）、库存数据滞后（ERP 与 WMS 不同步）。
- **打通用了 8 个月**：搭 CDP 用手机号 + UnionID 打通会员；统一尺码/颜色字典并建立映射关系；打通 ERP 与 WMS 实现库存实时同步。
- **定义了 80 个核心指标**，覆盖五个维度。

| 维度 | 指标 | 定义 | 目标 |
|------|------|------|------|
| 商品 | 爆款贡献率 | TOP20 SKU 销售额占比 | 40%–50% |
| 商品 | 新品存活率（30 天） | 上市 30 天动销 SKU / 新品 SKU | > 80% |
| 销售 | 售罄率（90 天） | 90 天销量 / 到货量 | > 70% |
| 销售 | 连带率 | 总件数 / 订单数 | > 1.8 |
| 库存 | 库存周转天数 | 360 / 库存周转率 | < 90 |
| 库存 | 库龄 > 90 天占比 | 超 90 天库存 / 总库存 | < 15% |
| 渠道 | 电商毛利率 | （电商收入 − 电商成本）/ 收入 | > 55% |
| 渠道 | 线下同店增长 | 老店同比销售增长率 | > 5% |
| 用户 | 复购率（180 天） | 180 天内再次购买会员占比 | > 35% |
| 用户 | 会员贡献占比 | 会员销售额 / 总销售额 | > 60% |

**上线一年后的实绩**：

| 指标 | 改善前 | 改善后 |
|------|-------|-------|
| 售罄率（90 天） | 58% | **73%** |
| 库存周转天数 | 112 天 | **85 天** |
| 库龄 > 90 天库存占比 | 22% | **12%** |
| 复购率 | 28% | **38%** |
| 滞销品打折力度 | 平均 5 折 | **7 折** |

## 六、三个常见坑

| 坑 | 表现 | 避坑指南 |
|----|------|---------|
| 只看总量不看结构 | 销售额涨了可能是打折打出来的；库存总量降了可能是畅销品缺货、滞销品压仓 | 总量与结构并重：看销售额同时看折扣率，看库存总量同时看库龄结构 |
| 忽略尺码/颜色维度 | 一个 SKU 总销量不错，但 M 码卖完、S 码积压 | 支持"款-色-码"三级下钻，每个 SKU 监控尺码分布 |
| 季节因素不考虑 | 拿冬装和夏装比售罄率没意义 | 同季节对比，同比优于环比，设置季节性基准 |

## 七、数仓侧：让口径落到工程约束里

### 四大标准库
- **业务术语库**：定义 GMV、DAU、有效订单等，每个术语明确业务定义、计算公式、统计口径、责任部门；与产品运营共创，在 Wiki 中维护并同步至数据地图。
- **数据字典/码值库**：集中管理枚举值（如 `order_status`：10 待支付 / 20 已支付），业务系统、数仓、报表系统都从此库获取，确保同源。
- **命名规范**：表名 `{层}_{主题域}_{业务过程}_{自定义描述}_{刷新周期}`，例如 `dwd_trd_order_pay_di`（交易域订单支付日增量事实表）；字段用小写蛇形且业务含义明确，如 `paid_amount`。
- **指标定义规范**：采用"**原子指标 + 修饰词 + 时间周期**"范式，例如"最近 7 天移动端 GMV" = 原子指标 `gmv` + 修饰词 `platform='mobile'` + 时间周期 `7d`。

### 标准落地与管控
- **设计时管控**：在数仓设计工具或数据开发平台内置标准检查，不符合规范无法提交。
- **运行时稽核**：每周扫描已上线表，检查命名与注释完备性，生成稽核报告。
- **实战关键**：把标准遵从度与项目上线强绑定——不符合规范的数据模型不予发布到生产。
- **成功度量**：新上线模型规范符合率 **100%**；核心业务术语与指标在平台中的统一维护率 **> 95%**；整体存储成本年增幅低于数据量增幅的 **50%**。

### 主题域与维度建模
- 电商主题域划分：**交易域**（下单/支付/退款/履约）、**流量域**（浏览/点击/搜索/分享）、**用户域**、**商品域**（SPU/SKU/类目/品牌/库存/价格）、**营销域**（活动/优惠券/广告）。
- 一致性维度：`dim_date`、`dim_product`、`dim_customer` 是跨主题域分析的基础。
- 星型蓝图（beefed）：三层 **raw → stg → mart**；`fact_sales` + `dim_date/dim_product/dim_customer/dim_store/dim_channel/dim_promo`；价格随时间变化的维度用 **SCD Type 2** 保历史；度量层提供统一口径，避免多口径并存导致决策混乱。

## 八、进销存指标与 SQL 口径（简道云）

| 指标 | 公式 | 说明 |
|------|------|------|
| 期末库存数量 | 上期库存 + 本期入库 − 本期出库 | 可按 SKU/门店/仓库统计 |
| 库存周转天数 | 期间平均库存 / 日均销售成本 | 平均库存建议 (期初+期末)/2 或按日周加权 |
| 动销率（门店） | 有销售 SKU 数 / 上柜 SKU 总数 | 反映款式动销状况 |
| 动销率（商品） | 有销售门店数 / 上柜门店数 | 反映铺货效果 |
| 上市 x 天售罄率 | 上市第 x 天累计销量 / 首批铺货量 | 常用 7/30/60 天，配合波段、天气、活动节奏 |
| 缺码率 | 缺码 SKU 数 / 计划 SKU 总数 | 尺码结构问题 |
| 断码率 | 某 SKU 库存 = 0 的门店数 / 该 SKU 铺货门店总数 | 补货不及时 |
| 补货满足率 | 实际补货数量 / 申请补货数量 | 供应与计划匹配度 |
| 调拨成功率 | 调出数量 / 调拨计划数量 | 调拨执行效率 |
| 残次率 | (退货 + 报损数量) / 销售数量 | 质量与售后风险 |

**SQL 六种写法**：LEFT JOIN + COALESCE 容错合并；窗口函数 `SUM(...) OVER(PARTITION BY ... ORDER BY ... ROWS UNBOUNDED PRECEDING)` 算时点库存；CTE 分层（`WITH raw AS (...), agg AS (...), final AS (...)`）；分组聚合 `GROUP BY product_id, date_trunc('month', move_time)`；条件聚合 `SUM(CASE WHEN move_type='IN' THEN qty ELSE 0 END)`；物化快照（每日库存余额写入 `snap_inventory_daily`）。覆盖常见业务问题约 **85%**。

**五条性能策略**：时间裁剪（强制 `WHERE move_time BETWEEN :start AND :end`）、覆盖索引（减少回表）、冷热分层（近 3 个月实时算、历史走快照）、月分区 + 并行聚合、高频指标预计算入表。综合效果 **IO 下降 68%、吞吐提升 2.3 倍**。

> 建议将指标口径沉淀为**只读视图**，供报表与 BI 统一引用，避免各部门口径分裂。
