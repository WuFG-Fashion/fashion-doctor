## 核心数据

- **Polars On-Prem**: 可在自有 K8s (EKS/AKS/GKE/minikube) 上一键 Helm 部署分布式集群，无需将数据发送到托管服务
- **Polars vs Spark 基准 (PDS-H, 1TB)**: 单节点 6.4x 快，分布式 3.2x 快（最快可达 38x）
- **1.42 自适应云 I/O**: Parquet/IPC 从对象存储读取的并发数根据带宽/延迟自动调优，平均 2x 提升，I/O 密集型查询最高 4x
- **1.42 矛盾过滤器消除**: 当谓词不可能满足时 (如 value > 100 AND value < 50)，优化器在计划阶段折叠查询为空结果，跳过扫描/过滤/聚合
- **1.41 嵌套公共子计划消除 (CSE)**: 扩展到每一层嵌套深度，共享子计划不重复计算（环境变量 POLARS_ALLOW_NESTED_CSPE=1 启用）
- **Parquet Footer 解码**: 手写 Thrift 解码器替代自动生成的，100 列 → 1.61x，1000 列 → 2.63x，10000 列 → 3.29x
- **流式引擎**: 1.40 支持分组 AsOf Join，持续扩展操作集合
- **Polars Cloud 0.9.0**: 表达式分布式运行、大型云 I/O 加速、分布式 Iceberg Sink
- **开源规模**: 575M+ 下载、38K+ GitHub Stars、13 个版本、435 PR、57 位贡献者（最近周期）
- **实际用户**: Optiver(量化交易)、Check(数据工程)、G-Research(机器学习)、GitHub、JPMorgan、Netflix、Databricks

## 关键要点

1. **Polars 正式进入分布式时代**：On-Prem 部署消除了"只能用单机"的认知误区，分布式性能 3.2x 超越 Spark
2. **优化器持续进化**：矛盾过滤器消除和嵌套 CSE 都是"无需改代码即生效"的优化，对服装零售 ETL（大量过滤条件）场景有直接收益
3. **云 I/O 自动调优**：多品牌数据分析系统从 S3/OSS 读取 Parquet 的性能将获得显著提升
4. **Polars vs Spark 基准为技术选型提供硬数据**：单节点 6.4x 意味着对中型服装集团（几百门店、几千万会员），单机 Polars 即可处理全量 ETL

## 服装零售场景映射

- **多品牌日销售汇总**: 流式引擎 + 自适应云 I/O → 从 OSS 读取 200+ 门店 CSV/Parquet，性能提升 2-4x
- **会员 RFM 计算**: 嵌套 CSE → 多品牌共用会员宽表去重计算，不重复扫描
- **库存预警过滤**: 矛盾过滤器消除 → 空库存查询直接折叠，零开销
- **K8s 部署**: 大中型服装集团可直接在内网 K8s 集群上部署 Polars 分布式集群，替代传统的 Spark 集群
