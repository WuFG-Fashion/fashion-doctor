## 一、VIP分层基础框架

### 1.1 RFM + 消费力三层模型

| 层级 | 定义 | 特征 | 运营策略 |
|------|------|------|----------|
| **钻石VIP** | 年消费≥5万 或 单笔≥3000 | 高频高额，核心利润来源 | 专属顾问、优先发货、新品预约 |
| **黄金VIP** | 年消费1-5万 或 季消费≥5000 | 稳定复购，成长潜力 | 生日礼遇、节日关怀、专属折扣 |
| **白银VIP** | 年消费3000-1万 或 新客6个月内复购 | 培育对象，提升空间大 | 积分加倍、满减券、唤醒触达 |
| **潜客** | 注册未消费 或 消费<3000 | 待激活 | 首单优惠、限时体验 |

### 1.2 消费周期分层

| 周期 | 最近购买距今天数 | 状态 | 召回策略 |
|------|----------------|------|----------|
| 活跃期 | 0-30天 | ✅ 健康 | 正常维护 |
| 沉默期 | 31-90天 | 🟡 预警 | 定向优惠触达 |
| 沉睡期 | 91-180天 | 🔴 危机 | 大额券+VIP专属活动 |
| 流失期 | >180天 | ⚫ 流失 | 重大节点召回 |

### 3.1 RFM 8组分层矩阵（2026实战版）

基于最近消费时间(R)、消费频率(F)、消费金额(M)三维划分8类人群：

| 分组 | R(近度) | F(频次) | M(金额) | 运营策略 | 预期ROI |
|------|---------|---------|---------|----------|---------|
| **重要价值客户** | 高 | 高 | 高 | VIP专属权益、新品体验官 | ⭐⭐⭐⭐⭐ |
| **重要发展客户** | 高 | 低 | 高 | 提升购买频率、连带推荐 | ⭐⭐⭐⭐ |
| **重要保持客户** | 低 | 高 | 高 | 防流失关怀、大额回购券 | ⭐⭐⭐⭐⭐ |
| **重要挽留客户** | 低 | 低 | 高 | 重点召回、原因调研 | ⭐⭐⭐ |
| **一般价值客户** | 高 | 高 | 中 | 积分激励升级、品类拓展 | ⭐⭐⭐ |
| **一般发展客户** | 高 | 低 | 中 | 首单后引导复购 | ⭐⭐ |
| **一般保持客户** | 低 | 高 | 中 | 维持联系频率 | ⭐⭐ |
| **低价值/流失客** | 低 | 低 | 低 | 批量触达或暂缓投入 | ⭐ |

## 四、实战操作规范

### 4.1 VIP判断标准（数据库字段）

```
-- 正确方式：判断 member_id 非空且非空字符串
WHERE member_id IS NOT NULL AND member_id != ''

-- ❌ 错误方式：使用 is_vip 布尔字段（可能不存在）
```

### 4.2 数据提取SQL

```sql
-- VIP分层查询（按消费金额分段）
WITH vip_stats AS (
    SELECT 
        member_id,
        SUM(amount) as total_amount,
        COUNT(DISTINCT DATE(sale_date)) as visit_days,
        MAX(sale_date) as last_visit
    FROM sales
    WHERE member_id IS NOT NULL AND member_id != ''
    GROUP BY member_id
)
SELECT 
    CASE 
        WHEN total_amount >= 50000 THEN '钻石VIP'
        WHEN total_amount >= 10000 THEN '黄金VIP'
        WHEN total_amount >= 3000 THEN '白银VIP'
        ELSE '普通会员'
    END as vip_tier,
    COUNT(*) as member_count,
    SUM(total_amount) as total_gmv,
    AVG(total_amount) as avg_amount
FROM vip_stats
GROUP BY 1
ORDER BY total_amount DESC;
```
