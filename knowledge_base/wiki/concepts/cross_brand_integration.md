## 1. 整合挑战与对策

| 挑战 | 具体表现 | 解决方案 |
|------|----------|----------|
| **品类不同** | A品牌有"西装"，B品牌没有 | 建立品类映射表，对齐到统一分类体系 |
| **价格带差异** | A品牌均价800，B品牌均价400 | 用倍数/百分比而非绝对值对比 |
| **店铺数量不同** | A品牌50店，B品牌200店 | 用均值/人均/坪效等相对指标 |
| **数据周期不同** | A品牌数据从2019起，B品牌2023起 | 标注有效数据范围 |
| **字段命名差异** | A叫`shop_name`，B叫`store_name` | 通过db_config做字段映射 |

## 3. 跨品牌对比分析维度

### 可以直接对比的维度
| 维度 | 指标示例 | 说明 |
|------|----------|------|
| **效率指标** | 售罄率/周转天数/未动销率 | 百分比/比值，不受规模影响 |
| **增长率** | 同比/环比 | 自身基准对比 |
| **结构占比** | 品类占比/渠道占比 | 内部结构比较 |
| **趋势方向** | 上升/下降/持平 | 方向性判断 |

### 需要谨慎对比的维度
| 维度 | 问题 | 处理方式 |
|------|------|----------|
| 绝对销售额 | 规模不同 | 展示但不直接排名 |
| 客单价 | 定位不同 | 分价格带组内对比 |
| SKU数量 | 策略不同 | 展示但不做优劣判断 |

## 4. 跨品牌SQL查询模板

```sql
-- 联合多品牌销售趋势对比（标准化为百分比变化）
WITH cabbeen_sales AS (
    SELECT date, SUM(amount) as amt 
    FROM cabbeen_sales WHERE date >= '2026-01-01' GROUP BY date),
pb_sales AS (
    SELECT date, SUM(amount) as amt 
    FROM pb_sales WHERE date >= '2026-01-01' GROUP BY date),
cabbeen_norm AS (
    SELECT date, 
           amt / (SELECT amt FROM cabbeen_sales ORDER BY date LIMIT 1) * 100 - 100 
           as pct_change FROM cabbeen_sales),
pb_norm AS (
    SELECT date,
           amt / (SELECT amt FROM pb_sales ORDER BY date LIMIT 1) * 100 - 100 
           as pct_change FROM pb_sales)
SELECT COALESCE(c.date, p.date) as date,
       c.pct_change as cabbeen_change,
       p.pct_change as peacebird_change
FROM cabbeen_norm c FULL OUTER JOIN pb_norm p ON c.date = p.date
ORDER BY date;
```

## 2026年8月6日更新（C轮 L2_06/07采集）

### ETL/ELT/ETLT 混合架构与多品牌归属边界（来源：FineDataLink 等电商数据工程四层栈，日期：**2026-08**，可信度：**高**）

- **90% 中大型企业不再二选一**，采用单平台双模式：核心交易/主数据/敏感报表走 ETL 前置清洗；海量日志/用户行为/实时分析走 ELT；全场景增量统一依赖 **CDC** 毫秒级
- **本项目的 ETL/ELT 归属边界**（防"两个销售额"）：

  | 数据域 | 模式 | 理由 |
  |-------|------|------|
  | 款-色-码主数据、品牌/组织/渠道字典、集团财务报表 | **ETL 前置清洗** | 唯一主键 + 统一编码，全集团口径一致 |
  | 门店 POS 流水、会员行为、埋点日志 | **ELT 入仓后建模** | 体量大、留全量原始数据供回溯 |
  | 全场景增量 | **CDC 统一** | 打通离线与实时 |

- **dbt 三层映射**：staging（按品牌一对一映射 raw 落地表）→ intermediate（品牌配置驱动统一清洗视图）→ mart（指标表直供看板）
- **⚠️ 混合陷阱**：若品牌配置清洗逻辑与仓内 SQL 视图各算一遍同一指标，逻辑分裂两处；三原则隔离：**不同源域 / 不同目标 schema / 清晰归属**
- **呈现层演进**：第三阶段加 ChatBI 对话入口，但必须继承多品牌数据隔离规则（权限复用），否则跨品牌数据在问答里越权泄漏
- 详见 [[2026-08-06_ETL_ELT_ETLT混合架构与电商数据工程四层]] [[2026-08-06_AgenticBI与ChatBI零售落地实测]] [[multi_brand_unified_analytics]]
