## 2. 多品牌核心设计理念

### 设计原则
| 原则 | 说明 | 实现 |
|------|------|------|
| **配置驱动** | 品牌信息不硬编码 | brand_config.py 统一管理 |
| **按需加载** | 只加载选中品牌的数据 | 查询时注入 brand 过滤 |
| **组件复用** | 相同分析逻辑跨品牌共用 | 抽取公共函数/类 |
| **渐进增强** | 先单品牌可用再扩展多品牌 | Tab切换隔离 |

### 品牌配置结构
```python
BRAND_CONFIG = {
    "cabbeen": {
        "name": "卡宾",
        "name_en": "CABBEEN",
        "db_path": "C:/Users/MacBookPro/cabbeen_data/cabbeen.db",

        "sub_categories": { ... },
        "colors": [...],
        "theme_color": "#000000",
        "shops": [...]
    },
    "peacebird_men": {
        "name": "太平鸟男装",
```

## 5. 扩展性设计

### 如何新增品牌
1. 在 `brand_config.py` 添加品牌配置
2. 创建对应数据库文件（结构一致）
3. 导入数据（脚本已支持）
4. 前端自动出现新品牌Tab

### 如何新增分析页面
1. 在 `pages/` 创建新py文件
2. 引用 `components/` 和 `core/` 的公共组件
3. 在 `app.py` 注册页面路由

- **多租户数据隔离三种方案对比**：

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| **共享表** | 成本低、实现简单 | 隔离性差、查询需过滤 | 中小SaaS/多品牌系统初期 |
| **独立Schema** | 逻辑隔离好、共享连接池 | 灾备复杂 | 中等规模多租户 |
| **独立数据库** | 隔离性最强、安全性高 | 成本高、维护复杂 | 大型企业/金融级 |

- **资源隔离策略**：计算资源按租户限流 + 存储容量配额管理
- **MyBatis-Plus / Spring 动态数据源**是主流代码实现方案
- **对Fashion Doctor启示**：
  - 当前SQLite每品牌独立db = "独立数据库"模式 ✅
  - 若未来扩展至10+品牌，可考虑"共享表+租户字段"模式降低维护成本
