## 二、JOIN 规范

### 2.1 shops 表 JOIN 规则

| 表 | JOIN 条件 | 原因 |
|---|---------|------|
| sales | `sales.shop_name = shops.short_name` | sales.shop_name 存简称 |
| inventory | `inventory.shop_name = shops.short_name` | 同上 |
| arrival | `arrival.receiver_name = shops.short_name` | 接收人即店铺 |

> ⚠️ **已踩坑**：不能用 `shops.full_name`，因为 sales 表存的是简称

### 2.2 字段名映射

| 实际字段 | 用途 | 常见错误 |
|---------|------|---------|
| `sales.shop_name` | 店铺简称 | 误用 full_name |
| `sales.sale_date` | 销售日期 | 误用 date |
| `sales.amount` | 销售金额 | 误用 revenue |
| `inventory.snapshot_date` | 库存快照日期 | 误用 date |
| `arrival.delivery_date` | 到货日期 | 误用 arrival_date |

## 三、日期处理规范

### 3.1 日期格式转换

```sql
-- ✅ SQLite 正确方式：显式转换日期
SELECT * FROM sales 
WHERE sale_date >= '2026-01-01' 
  AND sale_date <= '2026-04-29';

-- ✅ Python 日期处理：使用 relativedelta 避免闰年问题
from dateutil.relativedelta import relativedelta
end_date = start_date + relativedelta(months=1)
```

### 3.2 闰年处理踩坑记录

| 错误写法 | 问题 | 正确写法 |
|---------|------|---------|
| `date.replace(year=year+1)` | 2月29日→报错 | `date + relativedelta(years=1)` |
| `date.replace(month=month+1)` | 12月+1→跨年 | `date + relativedelta(months=1)` |

## 四、数据导入规范

### 4.1 CSV 导入前检查

```
□ 日期格式统一为 YYYY-MM-DD
□ 数值字段无千分位逗号
□ 无全角字符混入
□ 中文逗号检查（'，' vs ','）
□ 空值统一为 NULL
```

### 4.2 导入后验证

```sql
-- 1. 检查日期范围
SELECT MIN(sale_date), MAX(sale_date) FROM sales;

-- 2. 检查关键字段非空
SELECT COUNT(*) FROM sales WHERE shop_name IS NULL;

-- 3. 抽样对比原始数据
SELECT * FROM sales ORDER BY ROWID LIMIT 10;
```

## 五、异常数据识别

| 异常类型 | 识别方法 | 处理方式 |
|---------|---------|---------|
| 日期超出范围 | `WHERE sale_date > '2026-04-29'` | 标记待核实 |
| 负数金额 | `WHERE amount < 0` | 退货/冲销，需保留 |
| 超高单价 | `WHERE amount > 50000` | 团单/定制，需核实 |
| 重复记录 | GROUP BY + HAVING COUNT > 1 | 去重或合并 |
