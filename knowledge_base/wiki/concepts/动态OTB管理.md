# 动态OTB管理

> **一句话**：传统OTB季初定死→季中偏离15%是常态，动态OTB通过高频数据反馈、款式级决策和滚动调整实现精准管控。


## 结论

> **AI 合成洞察（判断 / 推论，非数据复述）**：
>
> 1. **季中 OTB 偏离 15% 是行业"默认失败"**：根因是信息频率跟不上市场——周/月汇总的决策节奏，对 7-14 天就变天的时尚而言等于盲人摸象。
> 2. **动态 OTB 的本质是"把预算从季初一次定死，改成款式级、3-7 天滚动"**：爆款 24h 识别、追单 3-5 天，尾货率可降 15-20%。
> 3. **规模是 OTB 的天敌也是 AI 的用武之地**：300 店×3000 SKU = 百万级决策组合，人工复盘 3-5 天，AI 把"看数→决策"压缩到实时。
> 4. **工具救不了流程烂**：AI 系统 ROI 依赖品牌规模与执行纪律，光买系统不建"有纪律的决策流程"，尾货率改善会落空（落地见 [[商品企划落地打法]]）。

## 核心要点

1. 季中OTB偏离计划15%以上是行业常态，根源是信息频率低于市场变化速度
2. 爆款识别滞后7-14天（周汇总），追单决策7-10天，数据驱动可压缩至3-5天
3. AI商品管理系统尾货率改善15-20%（部分客户数据），但品牌规模和执行影响效果
4. 300店×3000SKU=百万级决策组合，人工复盘需3-5天
5. 核心公式：高频数据反馈 + 款式级决策 + 有纪律的决策流程

## 详细内容

### 传统 vs 动态 OTB

| 维度 | 传统OTB | 动态OTB |
|------|---------|---------|
| 预算设定 | 季初一次 | 每3-7天滚动调整 |
| 决策粒度 | 品类级 | 款式级 |
| 数据频率 | 周/月汇总 | 每日/实时 |
| 追单周期 | 7-10天 | 3-5天 |
| 尾货率 | 基准 | -15-20% |

### 三大核心矛盾与解法

| 矛盾 | 解法 | 预期效果 |
|------|------|---------|
| 信息滞后7-14天 | 日粒度数据同步+自动化预警 | 爆款24小时内识别 |
| 品类预算vs款式决策 | 预算层级下钻+款式级利润评估 | 预算精准使用 |
| 多渠道库存不透明 | 统一库存视图(线上+线下+在途) | 消除重复/漏算 |

### AI辅助OTM ROI

| 指标 | 改善幅度 | 前提条件 |
|------|---------|---------|
| 尾货率 | -15~20% | 品牌执行配合 |
| 追单速度 | -50%以上 | 系统数据整合 |
| 买手人工复盘 | 释放3-5天/轮 | 系统自动化 |

### 实施路线图

1. **Day 1-30**：建立日粒度销售数据同步机制
2. **Day 31-60**：实现款式级利润与库存评估看板
3. **Day 61-90**：部署爆款/滞销自动预警规则
4. **Day 91+**：引入AI推荐引擎辅助追单/减单决策

## 2026-06-10 新增：滚动OTB与店群协同

### 滚动OTB操作周期
- 传统: 每月一次OTB复盘
- 数据驱动: **每周甚至每三天一次**
- 核心: 基于真实数据重新评估，而非简单"预算-已用"

### 店群协同分配
同一笔追单预算，应基于门店分层模型差异化分配:
- 高销门店 → 优先补货
- 低销门店 → 避免积压
- 模型输入: 历史销售能力+当前库存水位+区域市场特征

### 系统vs人工分工
| 角色 | 职责 |
|------|------|
| AI系统 | 数据整合+常规决策建议(百万级组合处理) |
| 商品团队 | 趋势研判+供应商谈判+新款引入+异常判断 |

## 2026-06-12 新增：买手店OTB落地公式

### OTB核心公式（买手店适用）

```
本月OTB = 本月销售成本 − 现有库存成本 ÷ 年周转次数
```

### 计算示例（女装买手店：月目标10万/定倍率2/库存8万/周转5）

| 步骤 | 计算 | 结果 |
|------|------|------|
| ① 销售成本 | 100,000 ÷ 2 | **50,000元** |
| ② 库存月消化 | 80,000 ÷ 5 | **16,000元** |
| ③ 本月OTB | 50,000 − 16,000 | **34,000元** |

### 买手店关键参数

| 参数 | 参考值 |
|------|--------|
| 定倍率 | 2～2.5倍 |
| 年周转 | 4～8次 |
| OTB复盘 | 每周一次 |

### 五条执行铁律

1. **OTB定死，绝不超支** — 超预算不拿，不管多好看
2. **全部按成本计算** — 拿货看成本，卖货看售价，口径统一
3. **只补动销款，不补感觉款** — 卖得快多补，不动销停补
4. **滞销不清，OTB不降** — 库存越乱，可拿货额度越少
5. **每周复盘一次** — 小调整不踩大坑

> 核心洞察：高盈利不是"多会拿货"而是"多会控制库存和现金流"

## 2026-06-15 新增：快反供应链对OTB的支撑——5件混批如何降初始订货

### 快反供应链改变OTB底层逻辑

武汉女装批发快反标杆（120+工厂/5件混批/滞销款调剂）揭示了OTB的新可能：

| 维度 | 传统模式 | 快反支撑模式 | 改善 |
|------|----------|-------------|------|
| 季前订货占比 | 100% | 25-40% | 风险集中度大幅降低 |
| 追单门槛 | 单款百件起 | 5件起灵活混批 | 测款→补货零障碍 |
| 追单周期 | 7-14天 | 天级极速补货 | -50%以上 |
| 滞销处理 | 被动折扣出清 | 主动滞销款调剂 | 库存风险前置管理 |
| 波段上新 | 2-4个波段 | 天天快速上新 | 售罄率动态优化 |

### OTB与快反的协同公式

```
有效OTB = 传统季初预算 × (1 - 快反可补比例)
         + 季中滚动预算（基于日粒度销售数据）
```

关键：快反渠道覆盖比例越高，OTB灵活度越大。120+工厂+5件混批使40-60%的货品需求可通过季中快反满足。

## 2026-06-17 新增：StyleMatrix现代OTB公式 + 双重计量体系

### OTB核心公式（StyleMatrix 2026-06）

```
OTB = 计划销售额 + 计划期末库存 + 计划降价金额 − 期初库存 − 在途订单库存
```

| 要素 | 说明 |
|------|------|
| + 计划销售额 | 预期销售目标 |
| + 计划期末库存 | 期末希望保留的库存水平 |
| + 计划降价金额 | 促销和清仓预留额度 |
| − 期初库存 | 当前已有库存 |
| − 在途订单库存 | 已下单尚未到货 |

### 双重计量维度
- **金额OTB**: 货币金额设采购上限 → 高价值/多样化产品线
- **单位OTB**: 数量控制采购 → 畅销基本款（防断货）

### OTB与OTR协同
OTB必须与OTR（Open-to-Receive，预期收货）对齐，确保产品准时到达——避免空货架（库存不足）和过剩库存（资金积压）。

### 现代AI增强
- AI需求预测→按品类/款式生成精准OTB目标
- 自动化预警：畅销品库存不足→触发补货
- AI趋势发现：历史销售+客户行为+实时趋势→新潮流
- 供应链同步：采购订单+交货周期+运输时间表联动

## 2026-06-19 新增：OTB采销公式细化 + SCM全链路协同白皮书

### OTB采销三位一体公式（知乎专栏 2026-01）

```
补充采购量 = 总采购量 − 已采购量
总采购量 = (已实现销量 + 未来销量) ÷ 预计售罄率
已上市补货量 = 可销售周数 × 每周销量 − 当前可用库存
```

- 季中/季尾售罄率不同，须参考历史数据
- 提前30-60天进行品类季度库存限额管控
- 品类存在库存缺口 → 补充采购（新品或已上市补货）
- 品类无库存缺口 → 严格控制采买

### 销售预测三要素
1. 前期业绩表现分析
2. 天气因素修正（骤然变冷透支需求 vs 迟迟不冷需求延后）
3. 品类结构变化追踪（消费者风向/天气导致品类切换如大衣减羽绒增）

## 最新补充（2026-08-07 · Round B）

### OTB 的"宽深拆分"可计算化（[[2026-08-07_单款店均效率SPS与款式宽度反推模型]]）

OTB 解决"买多少钱"，SPS 反推解决"买多少款"：

```
目标销售件数 = 目标销售额 ÷ 客单价
店均合理款数 = 目标销售件数 ÷ 门店数 ÷ 目标 SPS
企划总款数 ≈ 店均合理款数 × 1.3~1.5（含淘汰率）
```

参考区间：SPS 健康 ≥8 件 / 预警 <5 件；100㎡ 店上柜 120–180 款、200㎡ 店 200–280 款；超上限 20% 后**坪效不升反降**。

### OTB 额度的再分配规则（[[2026-08-07_retailnorthstar_SKU合理化五步减法与复杂度五区间]]）
SKU 合理化释放的采购额度按 **60/30/10** 分配：60% 加深核心款、30% 投新品类试水、10% 留季中翻单弹性——其中 10% 与季中滚动 OTB 的预留逻辑一致。

### OTB 决策的时间落点（[[2026-08-07_商品企划日历倒排周期与波段配比]]）
- 目标 OTB 总额定于 **T-9 月**（企划定调）
- 品类结构与宽深初稿定于 **T-8 月**
- 订货会 **T-3.5 月**、大货下单 **T-3 月**、首销复盘与翻单决策 **T+2 周**

> 宽深决策若拖到订货会临场做，SPS 反推就失去意义——**T-8 月是最后窗口**。
