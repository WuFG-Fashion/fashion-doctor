# 动态OTB管理

> **一句话**：传统OTB季初定死→季中偏离15%是常态，动态OTB通过高频数据反馈、款式级决策和滚动调整实现精准管控。

## 核心要点

1. 季中OTB偏离计划15%以上是行业常态，根源是信息频率低于市场变化速度
2. 爆款识别滞后7-14天（周汇总），追单决策7-10天，数据驱动可压缩至3-5天
3. AI商品管理系统尾货率改善15-20%（部分客户数据），但品牌规模和执行影响效果
4. 300店×3000SKU=百万级决策组合，人工复盘需3-5天
5. 核心公式：高频数据反馈 + 款式级决策 + 有纪律的决策流程

## 详细内容

### 传统 vs 动态 OTB

| 维度 | 传统OTB | 动态OTB |
|------|---------|---------|
| 预算设定 | 季初一次 | 每3-7天滚动调整 |
| 决策粒度 | 品类级 | 款式级 |
| 数据频率 | 周/月汇总 | 每日/实时 |
| 追单周期 | 7-10天 | 3-5天 |
| 尾货率 | 基准 | -15-20% |

### 三大核心矛盾与解法

| 矛盾 | 解法 | 预期效果 |
|------|------|---------|
| 信息滞后7-14天 | 日粒度数据同步+自动化预警 | 爆款24小时内识别 |
| 品类预算vs款式决策 | 预算层级下钻+款式级利润评估 | 预算精准使用 |
| 多渠道库存不透明 | 统一库存视图(线上+线下+在途) | 消除重复/漏算 |

### AI辅助OTM ROI

| 指标 | 改善幅度 | 前提条件 |
|------|---------|---------|
| 尾货率 | -15~20% | 品牌执行配合 |
| 追单速度 | -50%以上 | 系统数据整合 |
| 买手人工复盘 | 释放3-5天/轮 | 系统自动化 |

### 实施路线图

1. **Day 1-30**：建立日粒度销售数据同步机制
2. **Day 31-60**：实现款式级利润与库存评估看板
3. **Day 61-90**：部署爆款/滞销自动预警规则
4. **Day 91+**：引入AI推荐引擎辅助追单/减单决策

## 2026-06-10 新增：滚动OTB与店群协同

### 滚动OTB操作周期
- 传统: 每月一次OTB复盘
- 数据驱动: **每周甚至每三天一次**
- 核心: 基于真实数据重新评估，而非简单"预算-已用"

### 店群协同分配
同一笔追单预算，应基于门店分层模型差异化分配:
- 高销门店 → 优先补货
- 低销门店 → 避免积压
- 模型输入: 历史销售能力+当前库存水位+区域市场特征

### 系统vs人工分工
| 角色 | 职责 |
|------|------|
| AI系统 | 数据整合+常规决策建议(百万级组合处理) |
| 商品团队 | 趋势研判+供应商谈判+新款引入+异常判断 |

## 2026-06-12 新增：买手店OTB落地公式

### OTB核心公式（买手店适用）

```
本月OTB = 本月销售成本 − 现有库存成本 ÷ 年周转次数
```

### 计算示例（女装买手店：月目标10万/定倍率2/库存8万/周转5）

| 步骤 | 计算 | 结果 |
|------|------|------|
| ① 销售成本 | 100,000 ÷ 2 | **50,000元** |
| ② 库存月消化 | 80,000 ÷ 5 | **16,000元** |
| ③ 本月OTB | 50,000 − 16,000 | **34,000元** |

### 买手店关键参数

| 参数 | 参考值 |
|------|--------|
| 定倍率 | 2～2.5倍 |
| 年周转 | 4～8次 |
| OTB复盘 | 每周一次 |

### 五条执行铁律

1. **OTB定死，绝不超支** — 超预算不拿，不管多好看
2. **全部按成本计算** — 拿货看成本，卖货看售价，口径统一
3. **只补动销款，不补感觉款** — 卖得快多补，不动销停补
4. **滞销不清，OTB不降** — 库存越乱，可拿货额度越少
5. **每周复盘一次** — 小调整不踩大坑

> 核心洞察：高盈利不是"多会拿货"而是"多会控制库存和现金流"
