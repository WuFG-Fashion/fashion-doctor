# Pandas 3.0：Arrow原生架构革命（NumPy→PyArrow全面迁移）

> **一句话摘要**：Pandas 3.0 核心变革：底层从 NumPy 全面迁移到 PyArrow，Arrow String 30x 加速（100万行内存 80MB→12MB），Copy-on-Write 默认开启彻底消除 SettingWithCopyWarning，pd.col() 表达式向声明式演进。

## 核心要点

1. **NumPy → PyArrow 底层革命**：列式连续存储 + SIMD 指令级优化 + 零拷贝跨语言协同（Rust 可直接读取 Pandas 3.0 内存地址）
2. **Arrow String 30x 加速**：100 万行 6 字符代码内存从 ~80MB 降至 ~12MB，`str.upper()` 30x+ 提升
3. **Copy-on-Write 默认开启**：修改时自动创建副本，彻底消除 SettingWithCopyWarning，不再需要防御性 `df.copy()`
4. **pd.col() 声明式 API**：`df.select(pd.col("price") * pd.col("volume"))`，减少中间变量
5. **核心推动者**：Patrick Hoefler（牛津→Citadel），几乎凭一己之力重构内部索引逻辑

## 详细内容

### 字符串性能对比

| 指标 | 旧版 (NumPy Object) | 3.0 (Arrow String) | 提升 |
|------|-------------------|-------------------|------|
| 100万行6字符内存 | ~80MB | ~12MB | **6.7x** |
| str.upper() 计算 | baseline | 30x+ | **30x+** |
| CSV 读取 | 需手动 `engine='pyarrow'` | 自动最优 | 零配置 |

### Copy-on-Write 语义变化

```python
# 旧版：薛定谔的不确定性（可能影响也可能不影响原始 df）
# 3.0：确定行为
df2 = df["a"]           # 轻量级引用，零开销
df2.iloc[0] = 100       # 自动 Copy，df 不变
```

### Pandas 3.0 与 Polars 的分工

- **Polars 优势**：极致性能、LazyFrame 优化、零拷贝 Arrow 原生
- **Pandas 3.0 不可替代的价值**：
  - 拥有索引和 MultiIndex（Polars 没有且几乎永远不会加）
  - Scikit-learn / Statsmodels / 回测引擎生态（血管里流淌 Pandas 格式）
  - 无需脱离生态即可获得接近 Polars 的性能
