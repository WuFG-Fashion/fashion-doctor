# 服装零售指标口径统一与进销存SQL实践（2026）

> **一句话摘要**：服装零售数据分析的第一性原则是"一个 SKU、一套口径、一个真相"——把指标口径沉淀为**只读视图**供 BI 统一引用；进销存 SQL 六写法覆盖 85% 业务问题，五项性能策略实测 **IO -68%、吞吐 +2.3x**。

> **来源**：简道云进销存 SQL 方法 / 服装进销存最佳实践 / 服装 ERP 库存优化 + CSDN《服装行业指标体系搭建指南》+ Domo《Retail BI Complete Guide 2026》
> **最后更新**：2026-08-03

## 核心要点

1. **口径优先于查询**：多系统并行（ERP/电商/WMS/POS/财务）导致库存口径不一致、出入库时点不统一、在途与在库分离
2. **落地动作**：把指标口径沉淀为**只读视图**，报表与 BI 统一引用，避免部门口径分裂
3. **SQL 六写法**覆盖常见业务问题 **85%**；**五策略**实测 IO **-68%**、吞吐 **+2.3x**
4. **服装四个口径难点**：售罄率分母、周转天数分母、断码定义、"新品"天数窗口
5. **数据打通四统一**：SPU/SKU 编码、尺码/颜色标准化、时间口径（自然周月 vs 财周月）、渠道 ID

## 详细内容

### 核心指标口径对照

| 指标 | 公式 | 注意事项 |
|------|------|---------|
| 期末库存 | 期初 + 入库累加 - 出库累加 | 对齐时区，处理取消/冲销 |
| 库存周转天数 | 期末库存 / 日均销量 | 异常销量剔除 |
| 库存周转率 | 销售成本 ÷ 平均库存成本 | 另有"周期销售额/周期平均库存额"口径 |
| **售罄率** | **销量 / (期初库存 + 期间入库 - 退货)** | 分母是总到货量还是总采购量需先定义 |
| 动销率 | 有销售记录 SKU / 总 SKU | 识别僵尸 SKU |
| **断码率** | 有销售但缺某尺码的 SKU 数 / 在售 SKU 数 | 缺 1 码算不算需定义 |
| 毛利率 | (含税销售额 - 含税成本) / 含税销售额 | 折扣与返利口径一致 |

### SQL 六写法与五策略

| 六写法 | 用途 |
|--------|------|
| `LEFT JOIN + COALESCE` | 容错合并 |
| 窗口函数 `SUM(...) OVER(PARTITION BY ... ORDER BY ... ROWS UNBOUNDED PRECEDING)` | 计算时点库存 |
| CTE 分层 `WITH raw/agg/final` | 可读性与复用 |
| 分组聚合 `GROUP BY product_id, date_trunc('month', move_time)` | 形成月报口径 |
| 条件聚合 `SUM(CASE WHEN move_type='IN' THEN qty ELSE 0 END)` | 出入库拆分 |
| 物化快照 `snap_inventory_daily` | 加速 T+0/历史查询 |

| 五策略 | 做法 |
|--------|------|
| 时间裁剪 | 强制 `WHERE move_time BETWEEN :start AND :end` |
| **覆盖索引** | 查询字段被索引覆盖，减少回表 |
| 冷热分层 | 近 3 个月实时算，历史走快照 |
| 并行与分区 | 月分区 + 并行聚合 |
| 预计算 | 高频指标每日离线入表 |

**实测收益：IO -68%，吞吐 +2.3x。**

### 服装五维指标体系（CSDN）

销售（达成/同店/折扣/**连带率**）· 商品（爆款贡献/新品存活/价格带/款色码）· **库存（周转 + 库龄分布 30/60/90/120+ + 断码率 + 红黄绿灯）** · 渠道（直营/加盟/百货/奥莱 × 天猫/京东/抖音/快手/小程序/唯品会 × 直播/私域/小红书）· 用户（**复购率 + 风格偏好**）。

**服装最核心的库存指标是库龄与断码率——超 90 天基本是死库存。**

北极星指标按阶段选：初创期爆款贡献率 → 扩张期销售额/门店数 → 精细化期售罄率/周转天数 → 用户期复购率/LTV。

### 常用算法

- 需求预测：加权移动平均 + 节假日/促销活动系数；新品用同款型类比曲线
- ABC-XYZ：ABC 按销售贡献，XYZ 按需求稳定性；A/X 高服务水准 + 频繁补货，C/Z 低安全库存 + 快清理
- 动态安全库存：`SafetyStock = Z × σd × √L`（95% 服务水准 Z ≈ 1.65）
- 订货点：`ROP = 日均需求 × 供货周期天数 + 安全库存`，门店级需叠加最小展示量与尺码曲线

### 异常监控清单（可直接规则化）

库存负数 / 超安全库存 / 长期零销量；价格越界 / 折扣异常 / 毛利异常；在途超时 / 调拨滞留 / 退货异常；断码高发 / 尺码不均 / 颜色偏好异常。响应：看板告警 + 企业微信推送。

### 零售 BI 2026（Domo）

差异归结为 **Speed / Depth / Action**；选型需评估零售专属维度：数据连接性、延迟要求、**语义层支持**、AI 能力。最容易被低估的工作是跨源对账——"团队以为是几周的集成项目，结果发现是几个月的数据清洗"。
