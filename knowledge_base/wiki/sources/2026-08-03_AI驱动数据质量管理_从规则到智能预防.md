# AI驱动数据质量管理2026 — 从规则驱动到智能预防

> **一句话摘要**：2026 年数据质量管理从"被动修复"转向"主动预防"——Qualytics 客户平均在生产跑 **20,000+ 条规则、其中 95% 由 AI 推断生成**，并提出 **validate-at-use**（在数据驱动决策的那一刻校验）；硬边界是 AI 输出只能进确认流程、不能直接改生产数据。

> **来源**：surinch AI 驱动数据质量管理实战指南 + Qualytics Data Control Layer（2026-04-13）+ Atlan《Data Quality Rules for AI Success in 2026》+ Google Dataplex×Gemini Codelab（2026-03-28）
> **最后更新**：2026-08-03

## 核心要点

1. **AI 四类候选能力**：智能异常检测 / 预测性质量监测 / 根因分析辅助 / 修复建议生成 —— **全部需人工确认**
2. **上线硬边界**：AI 输出只能进入确认流程，不能直接改生产数据；关键节点必须人工审核（HITL）
3. **validate-at-use 范式**：AI 从"回答问题"转向"执行决策"后，坏数据以机器速度驱动自动化动作与财务过账，管道下游静态检查已经太晚
4. **规模实证**：Qualytics 客户平均生产运行 **20,000+ 规则**，**95% 由 AI 推断**；对外通过 **MCP** 向 ChatGPT/Claude/Copilot 暴露受治理的质量信号
5. **三个度量**：**Data uptime**（数据团队终极 SLO）/ **TTD** 检测时延 / **Data quality ROI**

## 详细内容

### 实施四阶段
现状评估和目标设定 → 数据质量基线建立 → AI 模型训练和验证 → 生产部署和持续优化。建议小范围试点验证后再扩展。

### 口径不一致排查的"先冻结七项"
当"源系统、数仓与报表结果不一致"时，先冻结 **截止时间 / 时区 / 粒度 / 过滤条件 / 晚到规则 / 口径版本 / 精度**，再判断是数据缺失、转换差异还是指标定义冲突。这与服装零售"一个 SKU 一套口径"的落地要求直接对应，见 [[2026-08-03_服装零售指标口径统一与进销存SQL]]。

### Atlan 六大实践与四大挑战

| 六大实践 | 要点 |
|---------|------|
| 按业务价值排优先级 | 抓驱动 80% 业务价值的 20% 数据元素 |
| **数据契约（Data Contracts）** | 在源头强制质量规则，生产者对进仓前数据负责 |
| 可复用规则模板 | 一次定义邮箱校验，复用于客户/员工/供应商 |
| AI + 主动元数据 | 2026 手工建规则无法规模化 |
| 自动化管家与修复 | 每条规则映射到具体 data steward |
| 透明沟通质量指标 | 通过率/趋势线/违规模式全员可见 |

四大挑战：碎片化下规模化难（中心枢纽质量高、源头质量差）、缺业务上下文、**规则腐化与告警疲劳**（schema 演进后误报激增→团队忽略告警）、修复瓶颈（无人认领）。

### policy-as-code 路径（Google Dataplex + Gemini）
Materialized View 打平嵌套数据 → Python Client 触发 profile scan → 导出 profile 喂给 Gemini CLI → 生成 Dataplex 规范 YAML 规则 → **HITL 验证** → 部署自动化质量扫描。目标是把治理规则纳入版本控制与 CI/CD。
