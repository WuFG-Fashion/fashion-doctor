# SQL优化2026向量化执行与PG18_DuckDB基准

> **一句话摘要**：2026 年 OLAP 进入「向量化执行 + 自适应查询」阶段：DuckDB 1.5.4 比 PostgreSQL 18.4 在 TPC-H 1TB 平均快 7.4x，`pg_duckdb` 1.0 让二者共存，混合架构零资源争用。

> **置信度**：第三方数据

## 核心要点

1. DuckDB 1.5.4「Variegata」(LTS 1.4.5 Andium)；`pg_duckdb` 扩展 2026 达 1.0，PG 内部可路由分析查询到 DuckDB。
2. TPC-H 1TB Parquet：DuckDB 比 PG17 平均快 7.4x；Q1 全表扫描 8.2 GB/s vs PG17 1.1 GB/s；3+ 表 JOIN 快 5.2x。
3. 向量化执行：120k 行 morsel + SIMD，CPU 缓存命中 40%→85%，单查询 3–10x。
4. 自适应执行：动态 Join/并行度，倾斜场景稳定 +60%、复杂查询 -40%。
5. 混合架构（PG OLTP + DuckDB OLAP）实测 138k 写/秒 + 7.8 GB/s、零争用；FinQore 管道 8h→8min（60x）。

## 详细内容

| 维度 | PostgreSQL 18.4 | DuckDB 1.5.4 |
|------|------|------|
| 执行模型 | 行式 Volcano + 并行 | 列式向量化(morsel/SIMD) |
| TPC-H 1TB 平均 | 基准 | 7.4x 更快 |
| Q1 扫描吞吐 | 1.1 GB/s | 8.2 GB/s |
| 3+ 表 JOIN | 基准 | 5.2x 更快 |
| 事务 | MVCC 强一致 | 单写多读(分析批处理) |

`pg_duckdb` 1.0 使「DuckDB vs PostgreSQL」不再是二选一：PG 保留事务与并发写，分析查询透明下沉到 DuckDB 列式引擎。

## 对本项目直接映射

- 本项目多品牌周报的聚合/即席查询（款号/色号/尺码/门店 group by/join）继续走 [[duckdb_olap_engine_2026]] 内存列式路线；OLTP 侧（销售入库 SQLite）保持事务模型。
