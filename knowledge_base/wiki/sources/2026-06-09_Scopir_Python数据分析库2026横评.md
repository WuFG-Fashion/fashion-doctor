# Python数据分析库2026全面横评（Scopir）

> **来源**：Scopir Blog（2026年发布）
> **覆盖**：Polars、DuckDB、Pandas 2.2、Modin、Vaex、DataFusion六库对比

## 核心数据

### TPC-H基准（PDS-H测试套件，2025年5月）

| 指标 | 数据 |
|------|------|
| TPC-H查询领先 | Polars在全部**22个**TPC-H衍生查询中均大幅领先Pandas |
| 能耗对比（合成数据） | Polars能耗约为Pandas的**1/8**（即Pandas的12.5%） |
| 能耗对比（TPC-H查询） | Polars仅消耗Pandas约**63%**的能量 |

### 各库定位

| 库 | 成熟度 | 核心优势 | 致命缺陷 |
|------|:---:|---------|----------|
| **Polars 1.x** | 稳定 | 惰性求值+并行+Arrow，速度领军 | 生态差距（可视化/ML需`.to_pandas()`） |
| **DuckDB 1.x** | 稳定 | SQL零拷贝，聚合/JOIN之王 | 非DataFrame原生API |
| **Pandas 2.2** | 成熟 | 生态无敌，<100万行首选 | 千万行以上性能断崖 |
| **Modin** | 稳定 | Pandas透明替代 | 内存更高/API不完整/小数据更慢（不推荐） |
| **Vaex** | 维护 | 超内存懒加载 | 社区萎缩 |
| **DataFusion** | 成长 | Rust/Arrow原生 | Python绑定尚浅 |

### 选型决策树

```
数据不到 100 万行？
  → Pandas（Arrow后端dtype），性能差异可忽略。

团队更习惯 SQL？
  → DuckDB，零学习成本直接写查询。

构建 Python 数据管道？
  → Polars，惰性求值+自动并行。

想直接查询文件而不加载？
  → DuckDB，SELECT FROM 'file.parquet'。

单机数据超过 1 亿行？
  → Polars（lazy模式）或 DuckDB。

数据大于可用内存？
  → DuckDB 或 Polars（streaming模式）。
```

### 团队适应期

- Pandas → Polars：约**1周**（概念一致，语法变化）
- Polars → Pandas：几乎即时（API更宽松）

## 关键结论

1. **Polars**是2026年性能优先场景的新标杆，PDS-H基准在22个查询中全面领先Pandas
2. **DuckDB**是SQL用户的最佳选择，聚合和JOIN表现突出，零拷贝集成Arrow生态
3. **Pandas**仍未过时，100万行以下小数据集不必迁移，ML生态无可替代
4. **Modin不推荐**——性能和兼容性两头不靠，API不完整且小数据反而更慢
5. 务必在自身工作负载上做基准测试——瓶颈高度依赖硬件、数据特征和查询复杂度
