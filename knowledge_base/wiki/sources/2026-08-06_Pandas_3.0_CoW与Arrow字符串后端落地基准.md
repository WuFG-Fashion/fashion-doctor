# Pandas 3.0 — CoW 默认化与 Arrow 字符串后端落地基准（2026）

> **一句话摘要**：pandas 3.0（2026-01-21 GA，3.0.4 于 06-28 发布）是十年来最大变更——Copy-on-Write 成为默认且唯一模式、字符串列默认切到 PyArrow 后端（内存 80MB→12MB、`.str` 操作快 5–30 倍）、新增 `pd.col()` 表达式与 Arrow PyCapsule 双向接口；代价是 Python 3.11+ 硬门槛与链式赋值直接报错。

> **来源**：pandas 官方 What's new 3.0.0 + 官网版本页 + PythonDataBench + SharpSkill + Quantide
> **最后更新**：2026-08-06

## 核心要点

1. **版本基线**：3.0.0 = 2026-01-21；**3.0.4 = 2026-06-28（当前稳定）**；官方建议先升 2.3 清警告再升 3.0
2. **CoW 唯一化**：任何索引操作与返回新对象的方法在 API 层面一律表现为副本；`SettingWithCopyWarning` 移除，链式赋值改抛 **`ChainedAssignmentError`**
3. **Arrow 字符串默认**：100 万个 6 字符编码列内存 **约 80 MB → 约 12 MB**；`.str.upper()` **提速 30 倍以上**；`.str.contains()/.str.lower()` **快 5–10 倍**；文本密集列内存最多降 **50%**
4. **`pd.col()` 表达式**：`df.assign(c = pd.col('a') + pd.col('b'))` 替代 lambda，语法借鉴 PySpark/Polars
5. **Arrow PyCapsule 双向**：DataFrame/Series 同时支持导出与导入，与 Polars/DuckDB/Rust 引擎零拷贝换手

## 详细内容

### CoW 的三条工程后果

| 变化 | 影响 |
|------|------|
| 链式赋值报错 | `df[df['A']>0]['B']=1` → `ChainedAssignmentError`，必须改 `df.loc[mask, 'B']=1` |
| `copy=` 参数失效 | 所有方法的 `copy=` 关键字不再有任何作用，可安全删除 |
| `inplace=True` 返回 self | `replace()/fillna()/ffill()/bfill()/clip()` 返回 self 而非 None，可链式 |
| `mode.copy_on_write` 弃用 | 设置该选项不再有影响，4.0 移除 |

主目标是**语义一致性**（消除"视图还是副本"的歧义），性能只是副产品——底层仍尽量用视图，只在真正写入共享数据时才复制。

### Arrow 字符串后端的内存机制

- 旧版：100 万行合约/款号列 = 100 万个 Python String 对象指针，每个都是堆内存独立对象
- 3.0：所有字符串内容紧凑存于一个连续大缓冲区 + 偏移量数组，C 层直接扫描连续内存

附带收益：`read_csv` 不再需要手动 `engine='pyarrow'`，自动选最优后端。

### 迁移断裂点清单

| 断裂点 | 迁移写法 |
|-------|---------|
| `df['col'].dtype == object` 判字符串 | 改 `pd.api.types.is_string_dtype(df['col'])` |
| 缺失值哨兵 | 统一为 `NaN`（不是 `pd.NA`） |
| PyArrow 数组不可变 | 转可写 NumPy 需显式 `.to_numpy(copy=True)` |
| Python 版本 | **最低 3.11**（3.0 起硬性要求） |
| setitem 非字符串到 str 列 | 直接失败（object 时代可以塞任意对象） |

### 对本项目的直接映射

- 本项目多品牌分析层大量以 **款号/色号/尺码/门店编码**等短字符串为主键做 groupby 与 join——正是 Arrow 字符串后端收益最大的形状，属于"升级即白拿"的场景
- CoW 消除了看板脚本里为消警告写的一堆防御性 `.copy()`，可在 [[streamlit_production_dashboard]] 的数据准备段做一次清理
- PyCapsule 双向接口让 pandas ↔ Polars ↔ DuckDB 三方换手真正零拷贝，坐实 [[arrow_zero_copy_interop_2026]] 里"Arrow 是数据栈 USB-C"的判断
- 升级前置条件是 **Python ≥ 3.11**，需与 [[python_dev_stack_2026]] 的 uv 环境基线对齐
