# 2026-03-02 百度开发者 SQL优化实战指南

> **一句话**：系统化SQL优化方法论，覆盖优化器原理、执行计划、索引设计和典型场景，可直接迁移至零售数据分析SQL优化。

## 核心要点

1. 覆盖四大核心模块：优化器原理→执行计划→索引设计→场景优化
2. EXPLAIN解读是SQL性能分析的起点：关注type/rows/Extra三字段
3. 联合索引必须遵循最左前缀原则，零售多维查询需精心设计索引顺序
4. 分页优化（延迟关联）、大表JOIN（小表驱动大表）直接解决零售BI性能瓶颈
5. 可无缝迁移至服装零售的销售/库存/会员查询优化

## 详细内容

### 四大模块

| 模块 | 核心内容 | 零售应用 |
|------|---------|---------|
| 优化器原理 | MySQL CBO成本模型、统计信息 | 理解为何索引"失效" |
| 执行计划分析 | EXPLAIN type/rows/Extra/possible_keys | 定位慢查询根因 |
| 索引设计 | B+Tree、最左前缀、索引下推ICP | 多维聚合查询索引设计 |
| 场景优化 | 分页/JOIN/子查询/排序 | 零售看板秒级响应 |

### 关键指标

- type字段：ALL(全表扫描)→index→range→ref→eq_ref→const，目标range及以上
- rows字段：预估扫描行数，越小越好
- Extra字段：Using filesort/Using temporary是性能杀手
