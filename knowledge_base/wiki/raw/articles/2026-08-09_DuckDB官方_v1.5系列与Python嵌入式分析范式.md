## 四、Python 侧：三套 API + 零序列化换手

- 硬门槛：**Python ≥ 3.9**；`pip install duckdb --upgrade` 或 `conda install python-duckdb -c conda-forge`。
- 三套接口并存：
  1. **DB-API**（标准 `execute/fetch`）
  2. **Relational API**（链式调用，体验接近 Pandas）
  3. **Spark API**（PySpark 用户几乎零学习成本）
- 与 Pandas / Arrow **几乎无序列化开销**地来回传递：

```python
import duckdb
# 直接查询内存中的 Pandas DataFrame，无需先建表
result = duckdb.sql("SELECT * FROM my_df WHERE value > 100").df()
# 直接读 Parquet，结果转 Arrow
arrow_table = duckdb.sql("SELECT * FROM 'data.parquet'").arrow()
```

- 两种运行模式：内存模式（默认，进程结束即消失，适合临时分析）与持久化模式（落盘文件，适合反复查询的数据集）。
- 核外（out-of-core）控制，可直接查数十 GB Parquet：

```python
con = duckdb.connect("analytics.duckdb")
con.execute("SET memory_limit = '8GB'")
con.execute("SET temp_directory = '/tmp/duckdb_spill'")
con.execute("""
    SELECT country, AVG(amount) AS avg_amt, COUNT(*) AS cnt
    FROM 'transactions_full.parquet'
    GROUP BY country HAVING COUNT(*) > 1000
""").fetch_df()
```

## 五、扩展生态

**官方核心扩展中使用频率最高的四个**：`httpfs`（HTTP/S3 访问）、`spatial`（空间数据）、`full_text_search`（全文检索）、`postgres`/`mysql`（直连其他数据库）。

历史版本能力回顾（1.2 版）：Google Sheets 扩展、SQL/PGQ 图查询（官方宣称在特定场景比 Neo4j 快 10–100 倍）、Arrow Flight 并发读写、新型列式格式 Vortex 原生支持。

**2026 年社区新玩法**：

| 项目 | 做法 |
|------|------|
| TypeScript 脚本作表函数 | 通过 `shellfs` + `arrow` 扩展把 TS 脚本输出喂给 DuckDB，实现对 REST API / GraphQL 端点的 SQL 查询 |
| DuckDB-Wasm + Iceberg | 浏览器里直接查 Iceberg 表，零安装零基础设施，计算在本地完成，**数据不离开客户端** |

| QuackFIX | 金融 FIX 协议日志的原生 SQL 解析扩展 |

## 六、定位与边界

- **不能全面替代 SQLite**：DuckDB 面向分析型 OLAP，SQLite 擅长大量小写入的事务型 OLTP。
- 单文件大小技术上无硬限制，生产中数十至数百 GB 常见，实际上限取决于磁盘与查询复杂度。
- Jupyter 支持良好：结果可直接返回 Pandas / Polars DataFrame，配合 `jupysql` 的 `%%sql` magic 在单元格里写 SQL。
- GUI：官方以命令行与库为主，第三方有 DBeaver / Tad，**DuckDB UI 自 1.3 起随发行版内置**。
- 许可：**MIT，个人与商业使用完全免费**，可集成进闭源软件，无订阅、无云依赖。
