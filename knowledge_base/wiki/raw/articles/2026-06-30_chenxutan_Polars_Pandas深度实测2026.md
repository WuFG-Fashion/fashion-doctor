## Polars三大架构支柱

### ① Apache Arrow 列式存储
- 同类型数据紧凑排列→CPU预取效率极高
- 压缩友好（Run-Length Encoding等）
- SIMD向量化：单指令处理多数据
- 零拷贝跨语言共享

### ② 懒执行（LazyFrame）
```python
df = pl.scan_csv('data.csv')           # ① 记录数据源
df2 = df.filter(pl.col('value') > 100) # ② 记录操作
df3 = df2.groupby('key').agg(...)      # ③ 记录操作
result = df3.collect()                 # ④ 优化后一次执行
# 内存峰值 ≈ 最终结果大小（vs Pandas ≈ 3x 数据大小）
```
- **谓词下推**：过滤条件推到数据源层，只加载匹配行
- **投影下推**：只读需要的列（100列只需2列，I/O减少98%）
- **操作融合**：合并多个操作为单次遍历

### ③ Rust多线程引擎
- Work-Stealing线程池：动态任务调度
- 无锁数据结构：避免锁竞争
- SIMD向量化：单指令处理多数据
- 彻底绕过Python GIL

## 架构差异关键表

| 维度 | Pandas（旧范式） | Polars（新范式） |
|------|----------------|-----------------|
| 存储模型 | 行式（NumPy数组） | 列式（Apache Arrow） |
| 执行模型 | 急切（立即物化） | 懒惰（声明式优化） |
| 并行模型 | 单线程（GIL） | 多线程（Rust原生） |
| 类型系统 | 动态（隐式转换） | 静态（显式Schema） |
| API风格 | 命令式 | 声明式表达式 |
| Index机制 | 单独存储+内存开销 | 内部整数索引，无额外开销 |
| 空值处理 | None→int变float | Null独立概念，不改变类型 |
| 流式处理 | 不支持 | streaming=True恒内存 |

## Polars 2026 v1.26 新功能

| 功能 | 说明 |
|------|------|
| 异步执行引擎 | `collect_async()` 非阻塞执行 |

| 流式处理 | `collect(streaming=True)` 100GB+恒内存 |

### 迁移策略
1. 新项目直接用Polars
2. 老项目渐进迁移：核心模块替换→API边界保留→逐步全替换
3. 互操作：`pl.from_pandas()` / `pl_df.to_pandas()`

> **信号**：当数据从"能放进内存"变成"放不进内存"，当等待从"秒级"变"分钟级"，就是迁移时机。
