# 服装全渠道 BI 三层角色看板实践

> **一句话摘要**：服装零售集团 BI 看板的"总部看全局、区域看趋势、门店看自己"三层分角色设计 + 预警分级上报 + 每视图 ≤7 指标的落地实操，可直接映射到 focus_brands 35 品牌（双核 cabbeen/peacebird + 品牌墙 + 女装补充）。
> **来源**：2026-08-26_服装全渠道BI看板三层角色设计与零售库存分析KPI
> **最后更新**：2026-08-26

## 核心要点

1. **看板三失效障碍**：不匹配角色（一套通用看板全员共用）、看到问题不能行动（看板与业务操作割裂）、异常靠人盯（无预警闭环）。设计出发点 = 决策与行动，不是数据展示。
2. **三层分角色**：总部看全局（一页看完+层层下钻）、区域看趋势（发现异常门店）、门店看自己（可执行操作）。
3. **预警分级上报**：一般异常黄标 → 重要异常主动推送 → 闭环跟踪。
4. **指标铁律**：每视图 ≤7 指标；看板有效 = 触发行动。
5. **多品牌映射**：三层只是同一指标层的不同视图，禁止各自建口径。

## 三层看板设计规范

### 总部管理层看板（"一页看完"）
- 核心指标：全渠道销售额达标率、各区域业绩排名、全渠道库存周转天数、高价值会员活跃率。
- 交互：支持 总部→区域→门店→SKU 层层下钻；异常时快速定位到具体区域/门店/SKU。

### 区域经理看板（发现差异信号）
- 核心指标：门店业绩排名、畅销品与滞销品排行、库存健康度分布、促销活动转化率。
- 日常动作：找出"谁在持续下滑、谁库存积压、谁缺货严重"并针对性处理。

### 门店店长看板（可执行）
- 核心指标：今日销售额与目标达成率、客单价与连带率、畅销款库存状态、会员开卡数。
- 重点：畅销款库存不足一键发起补货申请；待处理订单积压一键暂停接单。

## 预警分级上报设计

| 级别 | 触发条件 | 呈现方式 | 接收者 |
|---|---|---|---|
| 一般 | 库存周转天数连续 3 天上升 | 看板黄标标记 | 区域经理关注 |
| 重要 | 畅销款全渠道库存低于安全线 | 主动推送消息 | 商品部 + 对应区域经理 |
| 严重 | 缺货率 >5% 或填充率 <95% | 升级上报 + 闭环跟踪 | 总部商品总监 |

> 预警不是"发个通知就完"，而是分级 + 自动升级 + 闭环跟踪（处理状态在看板上可追踪）。

## Streamlit 落地要点

- 三层视图共用同一指标层（[[multi_brand_unified_analytics|多品牌统一分析架构]] 的语义层指标），页面层用 `st.fragment` 并行刷新分区。
- 大数据帧（SKU×店级明细）用 Streamlit 1.61 `st.dataframe` lazy loading + background cache refresh。
- 预警用 `st.toast` + 通知组件；一键补货/暂停接单通过按钮调用后端 API（看板与业务操作打通，不是"通知栏"）。
- 权限：总部全品牌只读 / 区域管辖品牌+区域 / 店长单店（复用多品牌数据隔离规则）。

## 与品牌数据的打通（品牌感知）

三层看板的分析对象 = focus_brands 35 品牌：
- 双核：[[peacebird]]（2026H1 门店 2861/毛利 61.2%/直营 14.42 亿+加盟 6.4 亿+线上 7.71 亿）与 [[cabbeen]]（门店 573/渠道结构 线下 53%+线上 42.2%+OEM 4.8%）——总部层天然按品牌×渠道下钻。
- 品牌墙 26 品牌：数据可得性分层（仅少数有财报级数据），看板必须标注置信度（财报/媒体估算），避免把估算当事实呈现。
- 售罄率/库存周转/缺货 KPI 与 [[sku_inventory_sql_operations]] 的分级 SQL 对接（爆款/畅销/平销/滞销四等级）。

## 结论

1. **看板项目成败取决于"角色-行动"匹配，与技术栈无关**：先定义三层各自的决策清单（总部要什么结论、区域要找什么异常、店长要触发什么动作），再定指标与交互——多数服装品牌 BI 沦为"数据大屏"的根因是反了顺序。
2. **预警分级 + 闭环是看板从"通知栏"变"驾驶舱"的分水岭**：黄标/推送/升级三级 + 处理状态可追踪，是把异常响应从"人盯看板"转为"系统盯人"的关键。
3. **多品牌场景下三层视图必须共享单一指标定义**：总部/区域/门店若各自建口径，就会重蹈"两个销售额"陷阱——这正是 [[multi_brand_unified_analytics]] 语义层（一处定义售罄率/周转/复购）要解决的核心问题。
