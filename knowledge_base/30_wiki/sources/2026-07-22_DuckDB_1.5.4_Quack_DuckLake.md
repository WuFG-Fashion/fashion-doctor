# DuckDB 1.5.4 + Quack核心扩展 + DuckLake 1.0 + v2.0路线图

> **一句话摘要**: DuckDB 1.5.4 (2026.6.17) 双版本发布: 全新 CLI(暗色/亮色) + VARIANT 类型 + GEOMETRY 类型 + Quack 客户端-服务器成为核心扩展 + DuckLake 1.0 投产 + v2.0 秋季亮相。

> **来源**: [DuckDB 官方](https://duckdb.org) + [DuckDB Lab](https://duckdblab.org) + [modb.pro 周报](http://www.modb.pro/db/2061993885853900800)
> **日期**: 2026-07-22

## 核心要点

1. **Quack 成为核心扩展 (v1.5.3)**: 客户端-服务器协议，HTTP 多实例共享同一数据库，v2.0 推生产就绪
2. **全新 CLI (v1.5.0)**: 暗色/亮色模式、动态提示符(db.schema)、`.tables` 命令、`_` 访问上次结果
3. **VARIANT 类型**: 原生 JSON/半结构化数据支持，1.5.4 修复过滤错误
4. **GEOMETRY 类型**: 内置空间类型，Parquet 统计修剪支持
5. **DuckLake 1.0**: SQL 数据库即 Catalog，湖仓最后一公里闭合
6. **Parquet Row Group Append**: 增量写入性能 10-100x
7. **Iceberg 增强**: MERGE INTO、分区表 INSERT/UPDATE、ALTER TABLE
8. **v2.0 路线图**: 2026 秋季发布，Quack 生产就绪

## 服装零售多品牌场景

| 特性 | 用例 |

| Iceberg MERGE INTO | 品牌级别增量更新全量表 |
| GEOMETRY | 门店选址/商圈热力图 |

## 结论

本页记录了DuckDB 2026年中的能力边界扩张：Quack协议成为核心扩展（客户端-服务器模式，HTTP多实例共享同一数据库），加上VARIANT类型（原生JSON/半结构化）、GEOMETRY类型、DuckLake 1.0（以SQL数据库作Catalog）与Parquet增量写入10-100倍提速。对多品牌零售分析而言，Quack解决的是「多个看板共享一份数据分析库」这一实际痛点——此前DuckDB的单进程嵌入模式难以支持并发访问。

## 前沿

Quack在1.5.3成为核心扩展但v2.0才推生产就绪，当前版本用于生产需评估稳定性风险。DuckLake 1.0「SQL数据库即Catalog」的运维复杂度（Catalog库自身的备份与并发）未讨论。Parquet Row Group Append的10-100倍提速区间跨度极大，实际收益高度依赖写入模式。v2.0计划2026年秋季发布，时间表可能变动。
