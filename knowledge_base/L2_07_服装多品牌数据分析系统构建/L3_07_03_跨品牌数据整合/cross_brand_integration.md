## 1. 整合挑战与对策

| 挑战 | 具体表现 | 解决方案 |
|------|----------|----------|
| **品类不同** | A品牌有"西装"，B品牌没有 | 建立品类映射表，对齐到统一分类体系 |
| **价格带差异** | A品牌均价800，B品牌均价400 | 用倍数/百分比而非绝对值对比 |
| **店铺数量不同** | A品牌50店，B品牌200店 | 用均值/人均/坪效等相对指标 |
| **数据周期不同** | A品牌数据从2019起，B品牌2023起 | 标注有效数据范围 |
| **字段命名差异** | A叫`shop_name`，B叫`store_name` | 通过db_config做字段映射 |

## 3. 跨品牌对比分析维度

### 可以直接对比的维度
| 维度 | 指标示例 | 说明 |
|------|----------|------|
| **效率指标** | 售罄率/周转天数/未动销率 | 百分比/比值，不受规模影响 |
| **增长率** | 同比/环比 | 自身基准对比 |
| **结构占比** | 品类占比/渠道占比 | 内部结构比较 |
| **趋势方向** | 上升/下降/持平 | 方向性判断 |

### 需要谨慎对比的维度
| 维度 | 问题 | 处理方式 |
|------|------|----------|
| 绝对销售额 | 规模不同 | 展示但不直接排名 |
| 客单价 | 定位不同 | 分价格带组内对比 |
| SKU数量 | 策略不同 | 展示但不做优劣判断 |

## 4. 跨品牌SQL查询模板

```sql
-- 联合多品牌销售趋势对比（标准化为百分比变化）
WITH cabbeen_sales AS (
    SELECT date, SUM(amount) as amt 
    FROM cabbeen_sales WHERE date >= '2026-01-01' GROUP BY date),
pb_sales AS (
    SELECT date, SUM(amount) as amt 
    FROM pb_sales WHERE date >= '2026-01-01' GROUP BY date),
cabbeen_norm AS (
    SELECT date, 
           amt / (SELECT amt FROM cabbeen_sales ORDER BY date LIMIT 1) * 100 - 100 
           as pct_change FROM cabbeen_sales),
pb_norm AS (
    SELECT date,
           amt / (SELECT amt FROM pb_sales ORDER BY date LIMIT 1) * 100 - 100 
           as pct_change FROM pb_sales)
SELECT COALESCE(c.date, p.date) as date,
       c.pct_change as cabbeen_change,
       p.pct_change as peacebird_change
FROM cabbeen_norm c FULL OUTER JOIN pb_norm p ON c.date = p.date
ORDER BY date;
```
