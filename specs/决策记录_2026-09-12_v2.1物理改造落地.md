# 决策记录：v2.1 物理改造落地（2026-09-12）

> 铁律⑪：每个关键决策一行「决策 + 为什么」。

1. **决策：逻辑分层字段先铺（2190 页回填），再做物理搬迁。** 为什么：specs §13.8 七步法的既定前提——没有 layer/scope/volatility 字段，物理分区后检索门禁无从生效；先铺字段可独立于搬迁验证。
2. **决策：MOC×8 + L3×2 死层移入 50_legacy 标 retired/never，不删除。** 为什么：v2.1 核心原则「软化不删除」，保留 git 历史与 as_of 时序点；RAG 经 retrieval:never 自然排除。
3. **决策：根 raw/（100 篇）并入 10_web（原 wiki/raw 783 篇）。** 为什么：实证同名交集=0，是历史残余分裂非内容重复，合并零冲突；双入口本身就是旧账。
4. **决策：八分区一次性物理成型（00/10/20/30/40/50/90 + brand_wall），不做渐进式。** 为什么：渐进式会让 tools 脚本与自动化规范长期处于"两套路径并存"的中间态，出错面更大；一次性搬迁 + pre-physical-migration tag 回滚点风险更可控。
5. **决策：tools 脚本与 7 份自动化规范同批改路径（step5），git add 仍禁整目录。** 为什么：路径漂移是搬迁后最高发故障；禁整目录纪律防止误提交数据文件。
6. **决策：Home.md 改为 build_home.py 脚本生成（T4 视图，禁手改）。** 为什么：旧 Home 手写停在 08-09 快照是 v2 架构的死层病根；视图层一律脚本生成是 v2.1 §12 的硬性设计。
7. **决策：断链扫描 107 条判定为既有模板占位符，不在本批修复。** 为什么：逐一核查均为 CLAUDE.md/log.md/_template.md 的文档示例，与物理搬迁无关；混入本批会污染迁移验证口径，另立清理批次处理。
8. **决策：验证通过后才推送 origin/main 并恢复全部 10 个自动化。** 为什么：搬迁期暂停自动化是为防写路径冲突；验证不过就推送会把破坏扩散到自动化产物。
