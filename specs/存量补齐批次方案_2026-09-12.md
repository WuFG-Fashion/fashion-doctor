## 二、修改要求（口径与原则）

### 2.1 frontmatter 字段口径（老板 2026-09-12 确认，最高优先级）

- **frontmatter 标签（字段）由 AI 推断填写**，不是人工精填。
- **确定不了 / 明确未知 → 一律填 `未知`**。
- 老板会自行修正需要修正的字段，AI **不必追求"准确值"、不必纠结**。
- 推断规则（能确定才填，否则填 `未知`）：
  - `layer`：entities/sources= T2，concepts/comparisons/practices/playbooks= T1
  - `scope`：品牌专属= brand，通用= public，公司域= company，个人= personal
  - `volatility`：方法论= evergreen，门店/组织= slow，季度财报/行情= fast，事件/联名= perishable
  - `as_of`：取"信息发生时点"（文件名日期优先），不确定填 `未知`
  - `expires_at`：fast= as_of+90天，slow= as_of+180天，evergreen 不填
  - `status`：默认 active
  - `confidence`：财报/官方公告/第三方数据/品牌自宣/媒体估算，分不清填 `未知`

### 2.2 补齐原则（铁律）

1. **只补不改**：只补缺失区块/字段，**不改写已有正文、结论、数据、双链**。
2. **软化不删除**：不删除任何内容；过期页降权不删。
3. **幂等**：补之前先检查该区块是否已存在，已存在则跳过（重复执行不产生重复区块）。
4. **分批提交**：每批完成后 `git commit`，可独立回滚。
5. **不碰历史快照**：`90_meta/_health/*.md`、`90_meta/log.md` 是 as_of 时序记录，**不改写**。

### 2.3 三个区块的填写规范

| 区块 | 填写要求 |
|---|---|
| `## 结论` | 1–3 句**合成判断**（不是照抄摘要），从页面已有「一句话摘要 + 核心要点」提炼 |
| `## 信息链` | 一行：`上游来源 → 本页 → 下游应用`，从 frontmatter 的 `sources`/`cross_refs` 生成，双链用 `[[文件名]]` |
| `## 前沿` | 有明确"下一步该查什么/哪个假设待验证"→ 写具体 1–2 条；没有 → 写 `暂无（本页已稳定）` |

## 三、执行步骤

### 步骤 1：补「结论 + 信息链 + 前沿」（合并一次遍历）

对每个缺区块的页（按批次表顺序）：

1. 读页面全文（frontmatter + 一句话摘要 + 核心要点 + 正文）。
2. 补 `## 结论`：提炼 1–3 句合成判断。
3. 补 `## 信息链`：`上游来源 [[...]] → 本页 → 下游应用 [[...]]`。
4. 补 `## 前沿`：有下一步写具体，否则写 `暂无（本页已稳定）`。
5. 写回：**保留原 frontmatter 和正文**，只在正文末尾追加缺失的区块（`结论`/`信息链` 放在正文靠前或末尾均可，`前沿` 放末尾）。
6. 三区块一次补全，避免对同一页二次遍历。

> 三个区块一起补，是因为 705 篇缺结论里 694 篇同时缺信息链，合并遍历最高效。

### 步骤 2：原料层 `wiki/` 残留清理（独立批次）

`knowledge_base/10_web/` 内 89 处 `wiki/` 残留，先甄别三类再改：

| 类型 | 示例 | 处理 |
|---|---|---|
| 内部路径 | `wiki/sources/xxx.md` | 改成 `30_wiki/sources/xxx.md` |
| 相对路径 | `[[../wiki/sources/xxx]]` | 改成绝对 `[[30_wiki/sources/xxx]]` |
| 外部 URL | `https://ima.qq.com/wiki/...` | **不动**（是外链，非内部路径） |

### 步骤 3：元文件断链收尾（独立批次）

- `30_wiki/index.md` 第 900 行附近的 `index_log_history_20260816-0824.md` 指向已删除文件 → 改文案为"历史登记归档，可从 git 历史找回"，不再指向具体文件。

## 五、风险与回滚

- 每批独立 commit，出错可 `git revert` 单批回滚，不影响其他批次。
- 补「结论」是"提炼"不是"照抄"，质量取决于 AI 判断；老板可后续修正（口径见 2.1，AI 推断、老板定稿）。
- 补区块**不得**改动 frontmatter 已有字段值（除非该字段缺失或值为空，才按 2.1 推断补入）。
